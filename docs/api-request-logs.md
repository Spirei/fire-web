# API 请求日志

## 入口与权限

- 管理员：日志 → 请求日志（`/activities?scope=requests`），或独立页面 `/api-requests`。
- `GET /api/request-logs` 返回概览、趋势、接口排行、分页明细及年度热力图。
- `GET /api/request-logs/events` 使用 SSE 通知记录变化，只有序号，不包含请求内容；最多 20 个同时订阅。
- 两个接口均验证管理员会话；未登录 401，普通用户及 App 授权无法读取全站请求日志。响应为私有、禁止缓存。

## 采集与存储

- Node 22 HTTP diagnostics channel 采集进入当前 Alcor Api 进程的 `/api/*` 请求。完成后记录时间、路由模板、方法、来源、最终 HTTP 状态与服务端处理耗时；客户端提前断开记为 499。
- 不记录查询参数、动态资源 ID、请求／响应正文、令牌、Cookie、IP 或完整 User-Agent。来源由请求头分类为网页、iOS、App 和其他，是请求特征推断，不是设备身份认证。
- 路由模板来自 `lib/apiRequestRoutes.ts`，`predev` / `prebuild` 自动重新生成；未知路径统一记为 `/api/[unmatched]`。请求日志自身接口和健康检查排除，避免自循环。
- 本功能记录进入 Web 的请求，不统计后台访问行情供应商的出站请求，也不回填启用前的历史。
- 每秒批量事务写入独立 `data/request-logs.sqlite`（SQLite WAL）；累计 512 条提前写入。数据库与 WAL/SHM 文件均为运行数据，不进入 Git 或镜像。
- 明细保留 7 天且最多 100,000 条；按小时汇总保留 31 天，按日汇总保留 400 天。明细过期不影响保留期内的统计及热力图。
- 磁盘故障时每 5 秒重试，内存队列最多 2,048 条，超过上限舍弃最旧记录；采集失败不打断业务响应。正常进程退出尽量落盘，强制终止可能丢失最后一秒未写入记录。
- Docker 复用现有 `/app/data` 挂载卷，重建容器保留历史。单进程实时通知；多进程共享同一个 SQLite 文件时通过 15 秒心跳检查序号补齐变化。

## 刷新与查询

- SSE 写入成功后通知页面；客户端合并通知、取消旧读取，页面隐藏时关闭订阅。EventSource 自动重连，30 秒读取兜底；SSE 响应带 `X-Accel-Buffering: no`。反向代理若强制缓存或缓冲事件流，需要为此路径禁用缓冲。
- 日志页签从 URL 直接生成服务端首帧与客户端显示，`scope=requests` 刷新不先显示用户日志；切换及前进后退使用同一个地址状态。
- 时间、状态、来源、方法、接口、选中日期、热力图年份及分页保存在 URL（`r*` 参数）；实时开关使用 `fire:api-requests:live` 持久化。
- 统计卡、趋势、接口排行及热力图采用同一组维度筛选；热力图展示所选全年，时间范围／选中日期只影响上方概览和明细。
- 日期统一按北京时间。今天或近 30 天内选中的单日显示小时趋势，其他日期显示日汇总。
- 明细每页 20 条，从第二页开始固定查询序号边界；实时请求不会把正在查看的旧记录挤到下一页。回到第一页重新跟随最新请求。
- 趋势柱支持鼠标查看、键盘聚焦和触摸点击；浮层显示该时段请求数和错误数。
- “常用接口”和请求明细自动识别 `/api/vN/` 路由并直接为路径中的 `vN` 段着色，与 API 文档路径、标题及版本入口共用配色。v1 灰色、v2 紫色、v3 青色，后续版本按调色板依次分配；深浅色均适配。版本根据路由模板判断，与请求来源、方法及成功／错误状态独立；无版本和未匹配路由不加版本标签。文档可用版本来自 `lib/apiDocsVersion.ts` 的固定文件登记，新增版本只需登记文档，无需修改标签或分页渲染，不允许读取未登记文件。

## 验证

`npm run test:review` 包含 `tests/api-request-logs.cjs`，在临时数据库验证真实 HTTP 状态／耗时、499、敏感字段排除、筛选一致性、翻页稳定、跨进程持久化、SSE、管理员权限、保留期及存储故障退避。不会向真实数据库写入测试记录。
