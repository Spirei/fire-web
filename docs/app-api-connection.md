# App API 连接与请求规范

本文件描述当前 PostgreSQL 平台的连接边界。接口字段沿用 [App API v2](app-api-v2.md) 与各业务冻结合约；Web、App 共用业务服务、财务数据、行情与汇率权威，不建立 App 专用行情或账户副本。

App 是主要服务对象，Web 可视化用于维护、配置和排查。现有正式 App 的接口稳定、延迟、字段与数据一致性优先，兼容修复由共享服务承接。

## 单地址接入与兼容演进

用户只填写一个 Alcor 网站地址；现有 App 已按同源发现结果确认版本并拼接业务路径，无需分别填写行情、账户、汇率或图表接口。供应商连接配置由服务端管理。新能力沿 v2 主线演进，现有 v1 与其他已公布入口共用业务服务并保留兼容；本约定不删除入口，也不让既有凭据自动换版本。

按模块读取保留按需加载、独立失败处理、缓存和授权边界；账户总额与盈亏使用有共同来源、币种及观测依据的财务快照，不由客户端把不同时点的局部和拼成完整总额。Web 界面、数据库或内部框架调整不改变这个合同。新增客户端界面可能需要 App 更新，兼容的服务端和供应商调整应由适配层承接。

变更前固定路径与方法、原信封和 JSON 类型、金额单位/精度、币种、时间/时段、空值、标识、分页、错误和权限。旧裸 JSON 继续由其适配层维护；新客户端 JSON 接口沿统一信封。兼容扩展使用可选字段和真实能力声明，不改变旧字段含义；破坏性变更须先给出显式迁移和客户端验证。供应商字段先规范为共享业务模型，保留来源、实际源时间及缺项，不通过补零、改名或直接转交供应商响应来获得表面一致。

## 连接与身份

- 新连接先匿名读取固定 `/api/v1/auth/config`，验证声明后读取同源固定 `/api/v2/auth/config`。来源、版本、grant 与权限绑定保存；网络失败、无效结构和 v2 不可用不能触发跨版本降级或改用 Web Cookie。
- App 私有请求只使用当前连接的 `Bearer fat_…`。服务端逐次验证实际令牌、期限、账号状态、权限与撤销记录；Redis 不保存认证成功结果。
- 原生登录、续期和撤销凭据请求可以不带 Origin 或 Authorization。网页入口按固定 v1/v2 与 client 路径转交内置服务，由同一后端校验实际来源及凭据；其他网页写入继续核对 Origin。转发服务暂不可用时，版本化接口仍返回统一 JSON、请求编号及恢复提示。
- 同一连接的令牌续期共用一个在途操作，凭据成对原子保存。续期不扩大 scope、不变更选定 API 版本；旧 refresh token 的重放规则保持。连接替换后的迟到结果不能覆盖新凭据。
- `40101/40102` 表示缺少有效连接或连接失效。`40301` 表示权限或来源不满足，不应因此循环刷新令牌或清除仍有效的连接。密码、验证码错误沿原业务错误码处理。
- `X-Alcor-Expected-Account` 仅用于核对当前已认证账号，不用于选择或授予账号身份。校验不一致时撤下原页面上下文，重新读取当前连接。

## 标识与响应

| 项目 | 规则 |
| --- | --- |
| 用户、记录等业务标识 | 按所属合约作为不透明字符串处理；旧编号与 UUID 都可能存在，不做整数转换或凭格式推断归属。 |
| 操作 `requestId` | 沿具体业务合约提供稳定 UUID；结果未确认时核对原回执，不换编号重复提交。 |
| `revision` | 沿服务端实际版本核对；冲突重新读取，不把请求编号当版本。 |
| JSON 信封 | 已公布 JSON 接口沿 `{code,message,data,meta?}`；错误的 `data` 可为空或省略，不将 HTML 当作正常结果。 |
| `X-Alcor-API-Version` | 与请求的 v1/v2 前缀一致，包括错误响应及公开汇率读取。 |
| `X-Request-ID` | 服务端本次请求关联编号，供排查连接故障；与业务原请求 UUID 分开保存。 |
| 缓存 | 私有和普通 JSON 读取使用 `no-store` 并区分 Authorization；公开交易日历保留原可缓存响应，敏感数据不进入公共代理缓存。 |
| 地址与方法 | 不以重定向修正 App API 地址。未知路径返回 404；已公布路径的错误方法返回 405 和 `Allow`。 |

令牌请求支持原 JSON 与表单协议。重复字段、无效 UTF-8、嵌套或数字令牌等畸形输入返回 `40002`，不执行轮换，也不作为凭据失效处理。

## 原 App 的迁入订单读取

`/api/v1/account-assets/orders` 与 v2 同一路径继续返回本人完整内部登记账本。原接口的 `local_trade_ledger / atomic_internal_orders` 读模型本来就包含 `legacy_internal_orders`、本人登记成交和明确观察成交，不等于券商成交证明。已封存的原表、完整版本、元数据表及来源归属核对通过时，适配层恢复这套读取；无元数据行沿原 LEFT JOIN 语义处理，不要求每笔都是新平台原子写入。缺表、版本、摘要或原归属无法核对的来源继续保留其登记历史表示，不用默认版本或空列表伪装完整。

迁入行保留 `source_registered_history`、原执行分类、原代码与历史锁定状态。供原 App 使用的代码按现有证券规则规范化，例如港股补足五位；本人当前记录的身份与修订号逐次核对，真实证券变化仍为不匹配。原历史券商归属按原现金关联、原费用证明或提交目标读取，与当前记录关联分开；迁入映射和当前账户不充当历史现金证明。按记录筛选的只读列表保留该记录原历史，不因当前账户不同而静默删掉旧订单；交易和现金写入仍要求其原账户与完整性条件。

发现声明沿已实现的同版本订单查询及原生待成交取消能力；声明不授予 `orders.cancel`。迁入 pending 保持挂起、不可管理，不恢复自动观察、附加单执行或归档执行授权。读取不向新交易/现金账重放订单，也不把历史覆盖、现金开账、实付费用、账户净值或服务端日盈亏改成完整。App 的原数量链、周期、日历、边界价和汇率校验继续生效。

## 请求耗时定位

同源 API 的 `Server-Timing` 只附加耗时和调用次数，不改 JSON、错误码或权限。`backend_ttfb` 是内置后端至响应头发出的时长，`pool_wait` 是取连接等待，`db_guard` 是实例、迁移与当前运行配置核对，`sql_execute` 是连接 `execute` 调用的等待合计；次数不包含单独游标调用。管理清单另记 `catalogue` 和 `json_encode`，冷生成与并发读者共用一个后台任务，取消单个读者不取消其他读者所需的生成。

读取预算另记 `read_admission_redis` 和 `read_admission_pg`，用于区分 Redis 计数与故障后数据库回退；两者同时出现表示该请求尝试缓存后使用了数据库，只有数据库段也可能处于缓存失败退避中。阶段只表示实际执行过的路径，不把缓存连通当作计数能力通过。

这些阶段可能包含彼此或并行，不能相加当作总耗时。响应头发出后冻结数值；后续流式传输和后台刷新不算首字节时长。没有 SQL、绑定参数、账号、令牌、原始地址或证券标识，也不向跨源客户端开放计时许可。网页转发保留该头；浏览器或 App 的完整请求时长还包含前置转发、网络和响应体读取，应分开核对。

## 并发、恢复与取消

- 身份、持仓、报价和行情订阅的只读核对使用共享身份锁，保持授权证明直到事务完成，避免同一 App 的独立读取互相串行。持仓列表与集合版本在同一事务快照内读取。
- 资产快照、总览、证券资料与回执读取在原券商身份和目录锁域内共享读取，并持有当前授权证明。券商、资金、交易与资料声明写入仍默认独占同一锁域；读取不升级为写锁，也不因优化跳过授权、归属、版本或完整性核对。
- 写入、续期及撤销授权保持原事务约束；现金、券商和交易读取保留原有金融锁顺序。共享读取不会放宽金融操作或撤销校验，也不增加权限。
- 原生授权行锁显式按账户 → 连接取得，与同步和券商读取保持一致，避免多表联接的行锁顺序与同步相反。首次账户查找仅决定锁目标，最终仍重查当前账户关系、令牌、范围、安全印记与失效状态；不缓存授权、不自动重放续期或写入。
- 普通只读请求可按失败类型有界恢复。只有确认无登记或写入意图的报价、图表 POST 才能按只读处理；带显式需求登记的请求继续按原 UUID 核对回执。
- 报价一分钟限流返回 `42901` 与 `Retry-After: 60`；登录的原十五分钟认证预算返回 `Retry-After: 900`。提示为保守等待窗口，不改变额度或自动授权重试。
- 连接池繁忙返回 503、`50001` 与 `Retry-After: 3`。临时故障不冒充 401，不清除有效连接；客户端避免立即循环重试。
- 个股详情与历史的 v1/v2 读取共用原每账户 60 次/分钟、全局 300 次/分钟预算，优先使用已配置 Redis，失效时沿用 PG。限流返回原 `42901` 和 `Retry-After: 60`；历史暂缺 503 保留 `50002` 并给出 `Retry-After: 30`，等待不表示已有历史或已接受采集，不自动重放写入。
- Redis 的 `PING` 成功只说明连接可达。读取预算的最小权限是本实例 `alcor:<instance-id>:read-budget:*` 键上的 `EVAL`、`INCR`、`TTL`、`EXPIRE`，另保留当前连接所需的命令；不需要全键、普通值读取、清库或 ACL 管理权限。部署后使用同一应用账号核对原子计数和过期，同时核对其他命名空间仍被拒绝，并确认原权限文件持久保存。不要为减少延迟关闭数据库同步落盘，认证限流不转入此缓存。
- 运行配置在每次取连接时重新核对全部保存者的当前管理员状态，合并查询不缓存授权；验证候选完成后才发布，取消或迟到旧版本不能清空当前行情源。请求日志每批最多 512 条流水写入，保持同一事务、原观察编号去重与失败续接，不逐条等待数据库往返。
- POST、PUT、DELETE、登录因子和令牌轮换不因超时或 5xx 自动重放。金融操作沿已有回执恢复；没有可核对回执的凭据操作按原连接流程确认。
- 离页、进入后台、切换账号或服务器时取消对应读取；共享请求只在最后一个观察者离开时结束。返回时重新验证来源、grant、版本与缓存代次。
- 行情、汇率或历史缺项保持未知。临时展示恢复不延长现金、报价或交易证明期限，不以空列表、零金额或旧授权掩盖读取失败。

## 验证入口

`platform/tests/test_app_connection_protocol.py` 使用隔离 PG 与实际 HTTP 路由，覆盖并发读取、读锁与续期互斥、初次认证后撤销、权限不足、账号不一致、限流、畸形令牌、无重定向及统一错误响应。相关身份、现金、持仓与行情测试继续核对原金融与授权合同。

这些服务端测试不代替发布后的 App 连接、模拟器或真机验收；源码、镜像、运行容器和 App 安装结果分别核对。

### 行情和历史采集

行情刷新统一在服务端调度，客户端读到期快照不会各自启动供应商请求。当前最新行情任务以完成后的五秒为下一次采集间隔；连续可见观察只续期原需求，不提前其已安排时间，重新唤醒休眠需求才立即入队。同一目标、本人来源许可、市场与时段最多二十只合并富途 SDK 读取，其他 HTTP 来源最多六个并发；每只证券保持独立租约、原件、源时间和迟到结果核对。每批处理完继续处理已到期需求，空闲才等待，历史仍有有界处理机会。

自动报价观察的需求续期仍要求当前 `portfolio.write`，以共享身份锁持有该权限证明；不把原生账户和连接锁成排他状态。行情需求域仍独占串行，UUID/CAS、容量和归属逐项核对。显式注册、取消与来源配置沿原独占身份核对；资产与同步读取可与自动观察并行，真实授权撤销仍不能越过进行中的证明。

`account-assets` 的行情范围按实际持仓选择，纯自选与历史目录不参与资产报价查询。官方来源或已核对持仓检查点仍按自身依据读取，数量未知不推断为零。原目录 DTO 保留，`active` 只表示当前持仓或有当前持仓证明但数量未全的记录；读取前后目录版本及账户持仓来源均须一致。

运行配置在独立候选中解密、验证管理员和当前实例后无异步等待地发布；原 Settings 不先重置为安装默认。读取取消不发布半份配置，较慢的旧修订不覆盖已核实的新修订；真实许可失效继续禁用相应目标。自动来源可选择其他当前已授权的实际报价，不能以旧许可数据、保存记录或接收时间冒充新行情。

供应商推送、Redis 最新快照与通知可沿此模型增强，但尚未实现的推送不能声明为已上线。Redis 不参与认证成功缓存，通知也不替代当前授权和版本核对；断线恢复始终读取完整当前快照。原 v1/v2 地址及返回格式继续兼容。

Web、v1、v2 共享同一份来源配置、证券身份、PG 观测和后台采集任务。普通美股报价 POST 按当前美东时段登记需求；返回的 `session`、`priceField`、`sourceTimestampAuthority` 表示实际取得的口径。`expectedSession` 仅表示当前请求意图，`extendedUnavailable` 表示尚未取得该时段报价。不得仅凭来源为富途或 Yahoo 认定已取得扩展行情。

富途快照仍报常规盘收盘时间时，盘前和夜盘可采用同一次受控 SDK 读取中的真实分时点与 `last_close`。空白点、其他证券、其他时段和未知基准拒绝发布；报价分钟时间与快照指标时间分别保留，不把请求时间写成成交时间。

| 方法 | 接口 | 请求 |
| --- | --- | --- |
| POST | `/api/v1/kline/prepare`、`/api/v2/kline/prepare` | `requestId` UUID、`items: [{market,code}]`（1–100）、`days`（1–3300）、`adjust`（none/qfq/hfq）、可选 `index` |
| POST | `/api/v1/portfolio-series/prepare`、`/api/v2/portfolio-series/prepare` | `requestId` UUID、`days`（1–1200）；证券范围由服务器读取本人持仓 |

这些入口需要当前网页登录或带 `portfolio.write` 的 App 授权，不接收用户编号、来源地址或私有主机。返回统一的 `code/message/data` 信封和已接受任务范围，复用原 UUID 可以查询原结果；后台完成前读取已有历史，切页不取消已接受的采集。已完成日线复用原件，数据不足时不生成收益率、净值或补零曲线。GET 历史读取保持只读。

行情 Worker 的实时与历史执行共用既有 PG 需求、来源许可、原始页面、断点和投影。实时单批最多 20 个独立任务，历史仅一个页面在途，共用 HTTP 并发上限 6；历史不会等待慢实时批次，也不会占用实时 SDK 通道。历史 SDK 使用独立的 `futu-history-read-v1` 私有流协议，只复用导入，不缓存观察值、不扩展原实时协议的动作。启动最多 45 秒、来源读取最多 12 秒，历史租约固定 90 秒，实时仍为 30 秒；过期或旧版本结果不能发布。每页仍在原授权核对事务中批量去重入库，未提交原件不冒充完整覆盖，原复权、来源和游标不变。

实时一批的至多 20 个租约在一次 PG 事务中领取并提交，再开始供应商读取，避免每只证券各等一次同步落盘。并行 Worker 通过原 `SKIP LOCKED` 分配互不重复的任务；每个任务仍有独立的所有者、版本、有限期限和发布前授权核对。回滚不留下部分领取结果，失效旧租约不能调用来源或发布数据，不合并证券原件、金融事务或请求回执。

原 App 未显式指定来源的个股历史沿共享自动选择：同一证券、周期、时段和复权口径只读取一个当前许可来源。日线先比较已观测的市场本地日期，同日按设置中的来源优先级选择，较旧补采片段不遮挡较新来源；不拼接不同来源的数据。显式 `X-Alcor-Market-Source` 继续严格绑定，普通规范历史读取仍保留多来源需显式选择的 409 语义。

指数的 `GET /api/v1/indices`、`GET /api/v2/indices` 在本人已有兼容行情配置时，与顶部及自选页读取同一份指数观测；显式指定的发现来源和匿名公共许可保持各自边界。`POST /api/v1/indices/prepare`、`POST /api/v2/indices/prepare` 接受 `{requestId}`，需要 `portfolio.write`，仅登记服务器固定指数身份。`open: null` 表示尚无已核实开市状态，不可当作休市；价格和时间的缺项保持未知。

腾讯 `tencent-minute-v1` 仅采集 CN/HK 常规盘单证券分钟价格，走同一来源许可、Worker 与原件核对；不视为 OHLC、实时成交时间或已规范化成交量。美股 ALL 分时继续使用明确许可的富途真实时间帧。指数与股票代码命名空间独立，App 不会把上证指数 000001 读作深圳同代码股票。

历史准备支持 `minute: true`（CN/HK REGULAR、US ALL）。`GET /api/v1/kline/preparations/{requestId}` 和 v2 对应路径只读返回本人原请求的 `pending`、`failed`、`state`、`unavailable` 和任务状态；需要 portfolio.read，不登记需求、不触发采集、不重发失败任务。页面等待原进度完成再读取图表；只有确认 failed 后才以新 UUID 请求备用源，未知提交先停止。

网页管理员读取 `/api/rates/provider?includeUrl=1` 可在当前有效验证下读取完整汇率地址；默认配置读取与 App 接口继续隐藏凭据。验证过期时返回 `urlRestricted: true`，网页通过 `/api/rates/provider/reauthenticate` 完成原身份校验后再读；显示地址不改变供应商配置，也不发起行情或汇率采集。

网页分析页的订单使用 v1 `{code,data:{orders}}` 包装，完整订单读取独立于历史行情与基准图；图表局部材料不得覆盖订单列表。素材目录 `marketCountsBasis: image-references` 表示图片引用数量，不是原件完整性回执；只有当前分页和图片响应执行原件校验。来源检测只返回固定错误分类，不包含 SDK 文本、目标凭据或供应商响应正文；行情与汇率 TCP 回退仅限本次 DNS 校验通过的已核准地址，保持同一连接总时限、TLS 主机验证和单次 HTTP 请求。

富途 Worker 保留单个有界 SDK 加载进程，先核对启动握手再发送证券请求；加载最多 45 秒，行情读取另限 12 秒。只读观察者在加载阶段取消时不发送其证券请求，下一次读取可接回同一受控加载；发出请求后超时或取消必须回收进程，迟到 stdout 不得成为下一证券的响应。来源检测共用同一次加载，美股按当前请求时段核对实际观测，不以连接测试的常规收盘价替代盘前、盘后或夜盘。

美股盘前与夜盘的 SDK 表示最多保留四个最近真实分时点；共享解码使用原件对应的接收时间选择已观测点，拒绝未来点、证券或时段不符、未知基准及同一时间冲突。接收时间与真实源时间分别保留，解码不读取当前墙上时钟，也不把接收时间写成成交时间。

固定公共行情的显式接入为 Tencent、Eastmoney、Yahoo 的已实现 HTTPS 主机和路径登记 `dns_policy: public_dns`；每次解析最多 32 个公网地址，混入任一私网、回环、链路本地、保留或多播地址即拒绝整次连接。TCP 只使用本次验证结果，TLS/SNI 保留原主机，不跟随跳转或重发 HTTP。旧 `pinned` 指纹不变，自定义、私有和汇率地址不获得此模式；接入仅升级本人已生成且主机和协议一致的目标，保留许可、市场、代码映射。既有公共模式再次接入不会因 DNS 轮换而重建来源。

隔离的本地验收遇到 Fake-IP DNS 时，可在私有启动 YAML 显式设置 `FIRE_QUOTE_DNS_MODE: approved_public_pins`，仅固定行情主机使用原已批准的公网地址，继续验证原许可路径与 TLS 主机，不信任或连接 Fake-IP。预发布及生产拒绝启用；默认仍走本次系统 DNS，自定义、私有和汇率目标不使用本地选项。

Yahoo Chart 请求恢复迁移前使用的 `User-Agent: Mozilla/5.0` 与 `Accept: application/json`，不增加 Cookie 或认证、不跟随跳转、不自动重试 HTTP 403/429，仍以真实供应商结果判断可用状态。

Yahoo 的行情与历史通过 YAML 的 `fire.environment` 直接配置 `STOCKLOG_PROXY: "http://proxy-host:port"`，使用显式 HTTP CONNECT 出口，不从 `.env` 引用；留空或 `"off"` 为直连。实际代理地址只留在群晖配置，不进入公开源码。修改后须保存项目并重建容器，随后用实际行情源检测确认；只重启旧容器不会更新环境。固定 Yahoo Chart 目标仍校验公网地址、原主机证书和实际响应，其他行情、汇率与自定义来源保持原连接方式。

### 数据库迁移的 App 兼容边界

迁移数据库或将内部读取改为 FastAPI，不改变已经公布的 v1/v2 路径、认证范围、标准 `code/message/data` 信封、UUID 回执或版本校验。当前兼容修复从原 App 模型和已有路由核对，补回已实现的 records、券商账户、资产快照与美港 A 股分时发现；没有核对完整的能力不因路由存在就宣称支持。客户端固定当前连接版本，不需要改地址或重新授权来取得这些修复。

总览、资产快照和完整个股详情读取同一份设置中的行情源及顺序，美股保留所选常规盘或实际观测时段。该选择层只读，不新增采集、不以保存价格冒充行情，也不改变显式来源读取的歧义校验。资产快照沿原 `schemaVersion:1` 补回本人资料和状态字段，缺失金额保留 null；原币现金来源完整性与换算完整性独立，缺汇率不隐藏已有账本证明的原币余额。快照未提供的当日订单与日盈亏明确不可用，不返回已核对空订单或零收益。
