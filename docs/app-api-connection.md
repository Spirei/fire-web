# App API 连接与请求规范

本文件描述当前 PostgreSQL 平台的连接边界。接口字段沿用 [App API v2](app-api-v2.md) 与各业务冻结合约；Web、App 共用业务服务、财务数据、行情与汇率权威，不建立 App 专用行情或账户副本。

## 连接与身份

- 新连接先匿名读取固定 `/api/v1/auth/config`，验证声明后读取同源固定 `/api/v2/auth/config`。来源、版本、grant 与权限绑定保存；网络失败、无效结构和 v2 不可用不能触发跨版本降级或改用 Web Cookie。
- App 私有请求只使用当前连接的 `Bearer fat_…`。服务端逐次验证实际令牌、期限、账号状态、权限与撤销记录；Redis 不保存认证成功结果。
- 原生登录、续期和撤销凭据请求可以不带 Origin 或 Authorization。网页入口按固定 v1/v2 与 client 路径转交内置服务，由同一后端校验实际来源及凭据；其他网页写入继续核对 Origin。转发服务暂不可用时，版本化接口仍返回统一 JSON、请求编号及恢复提示。
- 同一连接的令牌续期共用一个在途操作，凭据成对原子保存。续期不扩大 scope、不变更选定 API 版本；旧 refresh token 的重放规则保持。连接替换后的迟到结果不能覆盖新凭据。
- `40101/40102` 表示缺少有效连接或连接失效。`40301` 表示权限或来源不满足，不应因此循环刷新令牌或清除仍有效的连接。密码、验证码错误沿原业务错误码处理。
- `X-Alcor-Expected-Account` 仅用于核对当前已认证账号，不用于选择或授予账号身份。校验不一致时撤下原页面上下文，重新读取当前连接。

## 标识与响应

| 项目 | 规则 |
| --- | --- |
| 用户、记录等业务标识 | 按所属合约作为不透明字符串处理；旧编号与 UUID 都可能存在，不做整数转换或凭格式推断归属。 |
| 操作 `requestId` | 沿具体业务合约提供稳定 UUID；结果未确认时核对原回执，不换编号重复提交。 |
| `revision` | 沿服务端实际版本核对；冲突重新读取，不把请求编号当版本。 |
| JSON 信封 | 已公布 JSON 接口沿 `{code,message,data,meta?}`；错误的 `data` 可为空或省略，不将 HTML 当作正常结果。 |
| `X-Alcor-API-Version` | 与请求的 v1/v2 前缀一致，包括错误响应及公开汇率读取。 |
| `X-Request-ID` | 服务端本次请求关联编号，供排查连接故障；与业务原请求 UUID 分开保存。 |
| 缓存 | 私有和普通 JSON 读取使用 `no-store` 并区分 Authorization；公开交易日历保留原可缓存响应，敏感数据不进入公共代理缓存。 |
| 地址与方法 | 不以重定向修正 App API 地址。未知路径返回 404；已公布路径的错误方法返回 405 和 `Allow`。 |

令牌请求支持原 JSON 与表单协议。重复字段、无效 UTF-8、嵌套或数字令牌等畸形输入返回 `40002`，不执行轮换，也不作为凭据失效处理。

## 并发、恢复与取消

- 身份、持仓、报价和行情订阅的只读核对使用共享身份锁，保持授权证明直到事务完成，避免同一 App 的独立读取互相串行。持仓列表与集合版本在同一事务快照内读取。
- 写入、续期及撤销授权保持原事务约束；现金、券商和交易读取保留原有金融锁顺序。共享读取不会放宽金融操作或撤销校验，也不增加权限。
- 普通只读请求可按失败类型有界恢复。只有确认无登记或写入意图的报价、图表 POST 才能按只读处理；带显式需求登记的请求继续按原 UUID 核对回执。
- 报价一分钟限流返回 `42901` 与 `Retry-After: 60`；登录的原十五分钟认证预算返回 `Retry-After: 900`。提示为保守等待窗口，不改变额度或自动授权重试。
- 连接池繁忙返回 503、`50001` 与 `Retry-After: 3`。临时故障不冒充 401，不清除有效连接；客户端避免立即循环重试。
- POST、PUT、DELETE、登录因子和令牌轮换不因超时或 5xx 自动重放。金融操作沿已有回执恢复；没有可核对回执的凭据操作按原连接流程确认。
- 离页、进入后台、切换账号或服务器时取消对应读取；共享请求只在最后一个观察者离开时结束。返回时重新验证来源、grant、版本与缓存代次。
- 行情、汇率或历史缺项保持未知。临时展示恢复不延长现金、报价或交易证明期限，不以空列表、零金额或旧授权掩盖读取失败。

## 验证入口

`platform/tests/test_app_connection_protocol.py` 使用隔离 PG 与实际 HTTP 路由，覆盖并发读取、读锁与续期互斥、初次认证后撤销、权限不足、账号不一致、限流、畸形令牌、无重定向及统一错误响应。相关身份、现金、持仓与行情测试继续核对原金融与授权合同。

这些服务端测试不代替发布后的 App 连接、模拟器或真机验收；源码、镜像、运行容器和 App 安装结果分别核对。

### 行情和历史采集

Web、v1、v2 共享同一份来源配置、证券身份、PG 观测和后台采集任务。普通美股报价 POST 按当前美东时段登记需求；返回的 `session`、`priceField`、`sourceTimestampAuthority` 表示实际取得的口径。`expectedSession` 仅表示当前请求意图，`extendedUnavailable` 表示尚未取得该时段报价。不得仅凭来源为富途或 Yahoo 认定已取得扩展行情。

富途快照仍报常规盘收盘时间时，盘前和夜盘可采用同一次受控 SDK 读取中的真实分时点与 `last_close`。空白点、其他证券、其他时段和未知基准拒绝发布；报价分钟时间与快照指标时间分别保留，不把请求时间写成成交时间。

| 方法 | 接口 | 请求 |
| --- | --- | --- |
| POST | `/api/v1/kline/prepare`、`/api/v2/kline/prepare` | `requestId` UUID、`items: [{market,code}]`（1–100）、`days`（1–3300）、`adjust`（none/qfq/hfq）、可选 `index` |
| POST | `/api/v1/portfolio-series/prepare`、`/api/v2/portfolio-series/prepare` | `requestId` UUID、`days`（1–1200）；证券范围由服务器读取本人持仓 |

这些入口需要当前网页登录或带 `portfolio.write` 的 App 授权，不接收用户编号、来源地址或私有主机。返回统一的 `code/message/data` 信封和已接受任务范围，复用原 UUID 可以查询原结果；后台完成前读取已有历史，切页不取消已接受的采集。已完成日线复用原件，数据不足时不生成收益率、净值或补零曲线。GET 历史读取保持只读。

指数的 `GET /api/v1/indices`、`GET /api/v2/indices` 在本人已有兼容行情配置时，与顶部及自选页读取同一份指数观测；显式指定的发现来源和匿名公共许可保持各自边界。`POST /api/v1/indices/prepare`、`POST /api/v2/indices/prepare` 接受 `{requestId}`，需要 `portfolio.write`，仅登记服务器固定指数身份。`open: null` 表示尚无已核实开市状态，不可当作休市；价格和时间的缺项保持未知。

腾讯 `tencent-minute-v1` 仅采集 CN/HK 常规盘单证券分钟价格，走同一来源许可、Worker 与原件核对；不视为 OHLC、实时成交时间或已规范化成交量。美股 ALL 分时继续使用明确许可的富途真实时间帧。指数与股票代码命名空间独立，App 不会把上证指数 000001 读作深圳同代码股票。
