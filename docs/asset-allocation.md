# 全球预览 · 资产配置

入口 `/global?section=allocation`。服务端 `assetAllocation.ts` 为 Web、v1 与 v2 的唯一计算源；配置存在本人 `asset_allocation_accounts`，读取不修补原持仓、资金、银行卡或简化账本。

## 来源与核对

- 券商按现有分组 ID、币种关联全部非零持仓，未登记分组使用稳定名称散列；同一市场的不同券商保留独立节点。报价复用公共行情池；I/O 后重新读取持仓及现金，证券身份和版本变化时丢弃旧报价。缺报价采用已有记录价，`quoteStatus.missing` 明确记录，不伪造实时行情。
- 银行卡共用 `cardCashAccounts`，只计持有的借记卡、预付卡；应用核对覆盖后，只纳入已录非零余额的卡，未录及零余额卡不进入配置列表及汇总，原卡面库记录保留。已录非零金额但元数据损坏或缺汇率时仍保留异常，不伪装为完整总额。卡号、有效期、安全码不进入响应；卡面逻辑 ID 用散列映射为稳定来源 ID。
- 路由图与账户表将银行卡收拢为一个节点，点击查看各卡原币余额、显示币种估值及核对状态；`bankSummary` 由服务端对未排除的卡先汇总、再取两位小数，避免多卡独立取整后的差额。`count` 是所有非零余额卡数量，`includedCount` 是计入配置的数量，`value` 是显示币种合计，缺估值时为null。App可按同一字段与 `accounts.kind=bank` 展示分组和明细。
- 旧资金现金共用 `readAccountCash/reconcileAccountCash`。银行卡从该汇总拆出一次，其余作为「待归属现金」；没有可靠券商归属时不猜测分摊。旧简化主账户的市场权益已经计入该核算，不再叠加。
- 简化账本的独立现金、固定资产、其他投资、应收与负债按来源 ID 导入，换算只用服务端美元基准汇率；不使用简化账本个人 FX。重复记录同一笔资产时，通过「计入资产配置」显式排除重复来源。
- 关联券商的核对金额是该币种账户的含现金总权益。现金为核对权益减当前持仓；证券市值保留真实持仓，未叠加第二遍。核对是带时间的账单快照，后续原账本变化不改写人工核对值；「恢复自动关联」删除覆盖值。
- 核对券商后同币种待归属现金仍存在时，返回 `cash_overlap` 与空总额，要求核对来源后排除重复现金。缺余额、缺汇率、损坏账本同样保留 `null`。移除原来源后不会把旧核对值当成新增资产复活。
- `summary.portfolioTotalAsset` 是原 `/overview` 同口径总额；`totalAsset` 为本视图全部计入来源的已记录总资产，`netAsset` 扣负债；`difference` 为已记录净资产与原持仓总资产的差额。此视图包含固定资产等扩展范围，不替换原接口字段。完整性指已记录来源能够核算，不意味着未录入的外部账户已被发现。

关联持仓入口允许把现有未归属记录批量分配给已有券商。整批核对本人记录及revision后更新真实group_name，Web与App立即共用新归属；数量、成本、交易和报价不改。相关券商有人工核对时先恢复自动关联，防止拆分后沿用旧账户权益。

## App 与写入

`auth/config.asset_allocation` 声明路径和权限。v1兼容Web会话，v2只接受当前App连接；读 `portfolio.read`，写 `portfolio.write`。来源币种、类别不能被人工覆盖。写入严格白名单、有限金额、本人来源校验；`revision` 乐观锁，冲突409；恢复自动关联保留递增版本，旧表单不能在恢复后重新写入。账户切换头 `X-Allocation-User` 可拒绝旧页面向新账号写入。读取及请求体等待后重新验证认证。新增账户使用固定UUID requestId派生manual来源ID，重复提交拒绝且不会重复计入。恢复自动关联保留递增版本。

不自动重放写入；超时先读取确认结果，新增账户不自动重试。

## 读取合同与客户端生命周期

`snapshotRevision` 是包含账号、显示币种、全部来源、持仓版本、核算结果及行情状态的 SHA-256 语义指纹，排除每次变化的 `observedAt`。GET 返回弱 `ETag: W/"{snapshotRevision}"`，同一账号、同一显示币种下可携带 `If-None-Match`；相同返回304空正文，不解析JSON。每次200/304均重新鉴权、核对账号及最新来源；`X-Allocation-Observed-At` 给出本次核算时间，不能当行情成交时间。弱比较遵循 [RFC 9110 · If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-none-match)。账户写入仍使用来源 `revision`，快照指纹不可用作写入版本。

200/304均 `Cache-Control: no-store, private`，`Vary: Authorization, Cookie, X-Allocation-User`。客户端只保留当前内存快照；切换账号或授权失效清空，不持久化到账户共用的浏览器缓存。304必须有同账号、同币种、同ETag的已知快照；200校验合同、币种、账号、有限金额、分类及版本，避免代理错误页面或迟到响应覆盖数据。读取与写入都按账号限流（读 120 次/分钟、写 60 次/分钟），超出返回 429；30 秒刷新远低于该上限。

App发现新增 `snapshot_revision_field`、`conditional_read`、`checked_at_header`、读8秒/写12秒超时建议、30秒刷新建议及禁止自动重放写入。`source_connection=local-ledgers`、`external_institution_connections=false` 明确当前关联本站账本，未连接真实银行或券商账户。

Web读取采用单个在途请求，手动和后台读取可合并；保存成功后的读取取消保存前的请求。超时覆盖响应头与正文，错误保留旧快照；401/403/账号冲突清空旧快照。后台失败以30/60/120秒退避，工作区或文档隐藏时取消读取与动效，恢复时仅到期补读；未到期直接保留原布局。读取时间单独更新，304不替换节点。切换显示货币保留来源与路由，新换算到达前所有金额和表头继续使用旧快照币种，完成后一起更新，不闪回初始加载；快速切换丢弃旧请求。保存超时、响应无法确认或版本冲突时提供「重新读取」，不再次提交旧表单。

## 路由与动效参考

三列节点、SVG虚线、按真实DOM边界绘制贝塞尔线路及窄屏转为两列后向下连线，参考并改编自 [yetone/magpie](https://github.com/yetone/magpie) 的 `internal/gui/assets/routing.js` / `routing.css`（2026-10-07读取）。授权见 [Magpie MIT许可证](licenses/magpie-MIT.txt)。没有安装AI代理网关或把财务请求发送给Magpie。

光点沿真实线路移动的方式参考 [React Flow · Animating Edges](https://reactflow.dev/examples/edges/animating-edges) 的沿线圆点示例（2026-10-07读取），沿用原生SVG，没有引入新的图表库。保留左侧账户汇总到中间、右侧分类分叉的贝塞尔线路；光点到达中间左侧后，沿卡片实际上/下边框及圆角走到右侧，再进入分类分支，返程沿同一路径反向，不横穿净资产内容。窄屏分类在下方时从卡片下边框中心离开，沿分类列表左侧留白进入目标节点。光点使用类别颜色、柔和光晕及渐弱短尾迹；连线本身保持静止，同步期间提亮。

手动读取及保存后刷新时，每条计入账户线路并行向分布侧传递光点：单程3.2秒，线路间隔0.12秒开始（最多错开0.72秒）。快照返回后立即更新数据及读取状态，视觉去程完成后再反向一次；每个方向只走一次，慢请求等待期间不循环跳回起点。失败显示错误、保留旧快照，不播放成功返回。首次读取尚无已知线路时只显示读取状态，首次快照返回后播放返程。30秒后台检查保持安静，不重启动效；返回前台仅到期时补读，手动刷新立即读取或合并在途请求。卸载取消请求及两段定时器。金额隐藏遵循原偏好SSR恢复，减少动态效果禁用光点，不等待动画。

目前动效表达读取与返回；现有接口无法证明银行卡、券商已经自动连接外部机构或发生真实转账，因此没有把流动光点当成资金移动。未来有真实账户流水时，可用同一线路表达转入、转出和调仓。
