# 全球预览 · 资产配置

入口 `/global?section=allocation`。服务端 `assetAllocation.ts` 为 Web、v1 与 v2 的唯一计算源；配置存在本人 `asset_allocation_accounts`，读取不修补原持仓、资金、银行卡或简化账本。

## 来源与核对

- 券商按现有分组 ID、币种关联全部非零持仓，未登记分组使用稳定名称散列；同一市场的不同券商保留独立节点。报价复用公共行情池；I/O 后重新读取持仓及现金，证券身份和版本变化时丢弃旧报价。缺报价采用已有记录价，`quoteStatus.missing` 明确记录，不伪造实时行情。
- 银行卡共用 `cardCashAccounts`，只计持有的借记卡、预付卡；持有但未录余额的现金卡也列出待补余额，不作为零余额。卡号、有效期、安全码不进入响应；卡面逻辑 ID 用散列映射为稳定来源 ID。
- 旧资金现金共用 `readAccountCash/reconcileAccountCash`。银行卡从该汇总拆出一次，其余作为「待归属现金」；没有可靠券商归属时不猜测分摊。旧简化主账户的市场权益已经计入该核算，不再叠加。
- 简化账本的独立现金、固定资产、其他投资、应收与负债按来源 ID 导入，换算只用服务端美元基准汇率；不使用简化账本个人 FX。重复记录同一笔资产时，通过「计入资产配置」显式排除重复来源。
- 关联券商的核对金额是该币种账户的含现金总权益。现金为核对权益减当前持仓；证券市值保留真实持仓，未叠加第二遍。核对是带时间的账单快照，后续原账本变化不改写人工核对值；「恢复自动关联」删除覆盖值。
- 核对券商后同币种待归属现金仍存在时，返回 `cash_overlap` 与空总额，要求核对来源后排除重复现金。缺余额、缺汇率、损坏账本同样保留 `null`。移除原来源后不会把旧核对值当成新增资产复活。
- `summary.portfolioTotalAsset` 是原 `/overview` 同口径总额；`totalAsset` 为本视图全部计入来源的已记录总资产，`netAsset` 扣负债；`difference` 为已记录净资产与原持仓总资产的差额。此视图包含固定资产等扩展范围，不替换原接口字段。完整性指已记录来源能够核算，不意味着未录入的外部账户已被发现。

关联持仓入口允许把现有未归属记录批量分配给已有券商。整批核对本人记录及revision后更新真实group_name，Web与App立即共用新归属；数量、成本、交易和报价不改。相关券商有人工核对时先恢复自动关联，防止拆分后沿用旧账户权益。

## App 与写入

`auth/config.asset_allocation` 声明路径和权限。v1兼容Web会话，v2只接受当前App连接；读 `portfolio.read`，写 `portfolio.write`。来源币种、类别不能被人工覆盖。写入严格白名单、有限金额、本人来源校验；`revision` 乐观锁，冲突409；恢复自动关联保留递增版本，旧表单不能在恢复后重新写入。账户切换头 `X-Allocation-User` 可拒绝旧页面向新账号写入。读取及请求体等待后重新验证认证。新增账户使用固定UUID requestId派生manual来源ID，重复提交拒绝且不会重复计入。恢复自动关联保留递增版本。

不自动重放写入；超时先读取确认结果，新增账户不自动重试。

## 路由与动效参考

三列节点、SVG虚线、按真实DOM边界绘制贝塞尔线路及窄屏转为两列后向下连线，参考并改编自 [yetone/magpie](https://github.com/yetone/magpie) 的 `internal/gui/assets/routing.js` / `routing.css`（2026-10-07读取）。授权见 [Magpie MIT许可证](licenses/magpie-MIT.txt)。没有安装AI代理网关或把财务请求发送给Magpie。

请求发出后每条计入账户线路并行向分布侧飞行，快照返回后反向一次，数据立即更新，不为动画延迟。失败显示错误、保留旧快照，不播放成功返回。首次读取尚无已知线路时只显示读取状态。30秒前台读取、返回前台及手动刷新共用同一请求；卸载取消请求及定时器。金额隐藏遵循原偏好SSR恢复，减少动态效果禁用飞行及虚线运动。

目前动效表达读取与返回；现有接口无法证明银行卡、券商已经自动连接外部机构或发生真实转账，因此没有把装饰飞行当成资金移动。未来有真实账户流水时，可用同一线路表达转入、转出和调仓。
