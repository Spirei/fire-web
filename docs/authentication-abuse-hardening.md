# 登录注册防滥用 · v0.1.59

## 请求与账户边界

Web、v1 和 v2 密码登录／二次验证共用服务端预算。Web 注册只接受有界 JSON 对象、声明字段及真实字符串，拒绝对象／数组强制转换、额外权限字段和非 JSON 请求。用户名沿原有注册字符规则；密码按原值验证，不过滤 SQL 字符或截取密码。数据库身份查询和写入继续使用参数绑定，前端内容继续沿 React 原生文字转义。

原有来源校验、安装令牌、注册开关、密码强度、普通用户角色、双重验证、会话／grant 和 scope 边界保持。登录未知账户与错误密码沿统一错误，失败审计不写原始用户名或密码。没有新增默认大模型 Key、公开服务地址或密钥输出。

## 共享限流

以下是固定窗口，从该键首次接纳请求时起算；不是滑动窗口。

| 操作 | 同一来源 | 全站 |
| --- | --- | --- |
| 注册尝试 | 5 次／分钟，10 次／15 分钟 | 50 次／15 分钟 |
| 创建成功 | 1 个／分钟，5 个／24 小时 | 100 个／24 小时 |
| 密码登录 | 10 次／分钟，50 次／15 分钟 | 20 次／分钟，100 次／15 分钟 |
| 二次验证 | 12 次／分钟，40 次／15 分钟 | 30 次／分钟，80 次／15 分钟 |

无法核验代理来源时，所有请求归入共同来源，创建成功采用共同的 20 个／24 小时上限，其他窗口仍生效。IPv6 同一 /64 共用来源预算；IPv4 映射地址归一化。新来源键只保存 IP 摘要。原有账户维度 20 次／15 分钟等限制继续生效。

预算在 SQLite IMMEDIATE 事务内一次读取并接纳全部窗口，跨 worker／重启共享，即使 RATE_LIMIT_STORE=memory 也不回退为可绕过的安全预算。存储不可用返回 503；达到限制返回 429 和真实剩余 Retry-After。用户、会话和创建成功名额在同一外层事务中提交；重复用户名、写入失败和并发冲突不留下半个账户或消耗成功名额。

仅在服务确实由可信反向代理隔离时启用 FIRE_TRUST_PROXY_HEADERS。FIRE_TRUST_PROXY_HOPS 默认 1，从 X-Forwarded-For 的右侧可信端读取；多层代理按实际链路配置 1–16。入口代理须覆盖或追加可信地址，后端不能同时允许绕过代理的外部直连。请求头和链路数量有上限，非法配置归入共同来源，不能通过自填左侧地址增加额度。

## 客户端

网页和 iOS 原生页按 Retry-After 显示冷却，关闭重开保持，登录／注册／二次验证分别计时，iOS 另按服务隔离。内存中仅保存截止时间。发送期间阻止重复点击，冷却到期只恢复按钮，不自动提交。服务端限流始终是最终约束；刷新客户端、卸载或脚本直调不能取消服务端预算。

注册结果不明确时沿登录核验，不自动重放创建。原生限流反馈不会自动重新聚焦密码框，避免键盘与界面渲染竞争；离页、后台与身份变化仍清除秘密草稿并取消旧结果。

## 验证与发布

- 新增真实路由／临时数据库的 11 组滥用回归：字段类型、SQL／脚本输入、权限注入、非 JSON／超大请求、重复创建、限额、代理伪造及失败回滚。
- 4 worker／160 次竞争验证同一分钟创建额度只接纳 1 次；预算原子性、持久性和存储失败关闭通过。
- 实际网页处理函数的 3 组回归覆盖并发提交、关闭重开、独立冷却和二次验证。
- 原有 Web 身份安全、App 原生登录、完整 test:review、TypeScript 和隔离生产构建通过。生产模式只读冒烟 64 通过、0 失败；账户和业务写入测试均在临时数据库完成。
- iOS 0.2.285 原生界面 4 项方法通过，登录／注册限流分别覆盖深浅色、返回重进、前后台及显式重试；正常注册衔接和重复用户名同时通过。

源码按既有提交与发布流程交付；未发布的服务端改动不能视为线上已经生效。限流用于约束滥用规模，不等于已核验每个申请者的真实身份，也不宣称消除所有分布式自动注册。
