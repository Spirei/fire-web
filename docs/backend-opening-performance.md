# 后台打开速度优化 · 2026-09-26

## 本轮改动

- `RecordsApp.tsx`：仅持仓、资产分析、FIRE、盈亏分析和自选股启动持仓行情读取。设置、用户管理、卡面库等不再因打开页面启动无关的 30 秒轮询；切回资产页恢复原有刷新逻辑，手动刷新不变。
- `viewPreload.ts`：鼠标指向/键盘聚焦导航、移动端按下导航时预取目标页面代码。保持现有 SSR 与按页拆包，不提前挂载页面或调用其数据接口。去重，失败允许重试，省流量与 2G 跳过。
- `funds.ts`：余额在 SQL 内按币种聚合，不再排序并将全部流水分配为 JavaScript 对象。保留融资负余额、币种和账户隔离。
- `fundState.ts` / 后台 layout：首屏只算需要的总现金（含银行卡现金），省去未使用的资金分类汇总。

## 测量

临时数据库 20,000 笔流水、三币种、正负方向；各执行 9 次取中位数：旧 JavaScript 汇总 8.73 ms，SQL 汇总 3.45 ms，约减少 60%。仅代表该计算环节，不是整页提速比例。回归同时比较旧新结果并验证账户隔离。

本地 Next 开发服务、demo、设置页 HTTP 完整正文读取：优化前后三次暖请求分别为 71/75/73 ms 和 74/84/80 ms；没有可归因的整页时间改善。开发编译、HMR 与小规模真实账本使该短测不适合推出线上收益；不以冷编译请求作为前后对比。HTML 大小基本不变，此轮不是压缩页面内容。

## 验证

- 70 组隔离回归通过，包含新旧余额一致、负现金、预取去重、省流量、慢网络、失败重试。
- 55 项只读冒烟通过；类型检查、生产构建、diff 检查通过。
- Chrome 实测设置刷新、持仓与卡面库切换及最终数据加载，无控制台 error。
- 生产构建保持共享首屏 104 kB；后台仍按页动态加载，未把所有页面静态并入入口。

本轮未部署、未调整接口配额、未改真实账本或设计。未测线上低带宽与实体移动设备的端到端打开时间。
