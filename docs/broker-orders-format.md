# 券商订单导出文件格式规范（xlsx 导入）

> 本文档依据真实券商（长桥 H10891259）导出的两份历史订单文件（`Historyorders-*.xlsx`）观察归纳，是「订单系统 → 导入」功能解析 .xlsx 的依据。导入功能与导出功能共用同一套 21 列表头，因此本系统导出的文件也能原样导回。

## 1. 文件结构（OOXML）

- 文件是标准 **ZIP 容器**（本地文件头 `PK\x03\x04` + deflate 数据 + 中央目录 + EOCD），内容为 OOXML 文本。
- 必须存在的条目：`[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、`xl/_rels/workbook.xml.rels`、`xl/worksheets/sheetN.xml`。
- **单元格用 inlineStr（`<c t="inlineStr"><is><t>…</t></is></c>`），没有 sharedStrings.xml**。解析时不要依赖共享字符串表。
- 数据工作表以 **A1 = `订单状态`** 为识别标志（第一份文件首个 sheet 即为数据表；`wb:workbook` 的 sheet 顺序即工作表顺序，sheet1 是主数据表）。不要读取「汇总 / 统计」类 sheet。

## 2. 表头（21 列，A–U）

| 列 | 表头 | 类型 | 说明 |
|----|------|------|------|
| A | 订单状态 | 文本 | `已成交` / `已过期` / `已撤销` / `已拒绝` |
| B | 市场 | 文本 | `US` / `HK` / `CN` … |
| C | 股票代码 | 文本 | 含交易所后缀，如 `SPCH.AM`；港股纯数字 `2580`；期权如 `NVDA250926C185000` |
| D | 股票名称 | 文本 | 券商侧名称（可能带发行商 / 倍数旧写法，导入时按命名规范规范化） |
| E | 方向 | 文本 | `买` / `卖`；含 `股息` / `红利` / `分红` / `派息`（或业务类型列含这些词）按股息入账，不改变持仓数量与成本，每股股息 × 股数记为现金收入 |
| F | 委托类型 | 文本 | `限价单` / `到价买入` / `到价卖出` 等 |
| G | 委托数量 | 数字 | 委托数量（整数或小数） |
| H | 委托价格 | 数字 | 限价；`到价单` 为触发价 |
| I | 触发价格 | 数字 | 非到价单为 `--` |
| J | 币种 | 文本 | `USD` / `HKD` / `CNY` … |
| K | 委托时间 | 文本 | `YYYY-MM-DD HH:MM:SS ET`（美股，美东时区）；港股无后缀 `YYYY-MM-DD HH:MM:SS`（北京时间） |
| L | 成交均价 | 数字 | 未成交为 `0` |
| M | 成交数量 | 数字 | 未成交为 `0` |
| N | 成交金额 | 数字 | 成交数量 × 成交均价 |
| O | 剩余挂单数量 | 数字 | |
| P | 撤/废单数量 | 数字 | |
| Q | 有效期 | 文本 | `撤单前有效` 等 |
| R | 时段 | 文本 | `盘中+盘前盘后` 等 |
| S | 触发状态 | 文本 | `未触发` / `已触发` / `已失效` |
| T | 订单号 | 文本 | 全局唯一（如 `1269385364817096704`），跨文件可能重叠 |
| U | 驳回原因 | 文本 | 通常为空 |

> 注意：**不要用固定列索引取值**。行内单元格按 `r="A1"` 引用定位列字母（含空白单元格补齐），再按表头行映射字段名；这样表头顺序变化也安全。

## 3. 时间格式与时区

- 美股（B=US）：`2026-08-04 16:04:15 ET` —— 美东时间（America/New_York，含夏令时），导入时转 UTC 存储。
- 港股（B=HK）：`2026-02-25 09:41:01` —— 无后缀，按北京时间（Asia/Hong_Kong）解析。
- 导入后统一存 ISO 8601 UTC（`…Z`），页面按本地时区展示。

## 4. 状态语义与导入规则

| 订单状态 | 是否导入 | 说明 |
|----------|----------|------|
| 已成交 | ✅ | 仅导入此类。要求 成交数量 > 0 且 成交均价 > 0；`--` / 0 的行跳过 |
| 已过期 | ❌ | 未成交，丢弃 |
| 已撤销 | ❌ | 未成交，丢弃 |
| 已拒绝 | ❌ | 未成交，丢弃 |

- **去重**：两份导出可能有重叠，按 订单号（T 列）去重；已存在于 `trade_orders.order_no` 的订单跳过（幂等，重复导入不产生重复数据）。
- **代码归一化**：剥离交易所后缀 `.AM` / `.N` / `.OQ` / `.PS` / `.K`（`SPCH.AM` → `SPCH`）后与 records 匹配。
- **净量校验**：每股按时间顺序重放成交，位置快照（`position_qty_before/after`、`position_cost_before/after`、`realized_pnl`）逐笔自洽；**重放最终数量必须等于记录当前数量**，否则整组跳过（如 SKHY：买 26 卖 25 净 +1，与零持仓矛盾，判定导出缺单）。
- **记录匹配**：命中已有记录 → 挂到该记录；未命中 → 新建记录（qty/cost 置空，归入「全部」+ 对应市场分组，名称按命名规范规范化）。
- **期权**（代码形如 `NVDA250926C185000`）：股票记录体系不支持，跳过。
- **窗口外持仓**：只有卖出、买入在导出窗口之外（如 HK 2580 / 2824 单边卖出）→ 以「窗口外基准数量」导入、成本未知置空，仅作历史留痕。

## 5. 快照与对账

- 导入时按成交时间升序重放：买入加权成本（`position_cost_after = (before·cost + qty·price) / after`），卖出记录已实现盈亏 `(price − cost) × qty`。
- 导入完成后校验：订单快照链连续、最终数量与记录数量一致、无悬空 `record_id`、订单号无重复。

## 6. 与本系统导出的兼容

本系统「导出订单」生成的 .xlsx 使用同一套 21 列表头（A1 = 订单状态、inlineStr 单元格），因此可以互相导回；导入端解析逻辑与导出端写入逻辑对称。
