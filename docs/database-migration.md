# 数据库迁移

入口：系统 → 备份与恢复 → 数据库迁移。左侧为旧库，右侧为当前平台的新库。

## 连接

- 新库始终读取服务端 `FIRE_DATABASE_URL`、`FIRE_INSTANCE_ID` 和环境标记。页面只展示脱敏信息、重新读取和测试连接，不保存第二套运行库配置。
- 旧库可由管理员填写主机、端口、数据库、Schema、账号、密码和 TLS 模式。密码通过现有 Vault 加密保存；响应、任务回执、日志和页面均不回显密码。旧库连接不写入 `.env`，也不调用运行库的连接切换。
- 每次保存产生独立配置版本。更换地址、库名、端口或账号不得继承另一目标的密码。修改配置后，旧连接检查、预览和演练均不能作为新版本的执行依据。
- 连接测试只开启只读事务，核对实际数据库、角色、Schema 与读取权限。禁止选择当前运行数据库或相同平台实例作为迁移来源。连接成功仅证明本次检查成功，不能代替后续备份、结构适配和对账。
- 非 `public` 来源必须显式绑定 Schema，所有来源目录、所有者核对、数据查询和关联子查询均限定该 Schema，不能依赖会话 `search_path`。

## 执行顺序

1. 核对两边身份、版本、数据范围、文件目录与剩余空间。
2. 分别备份旧库和当前新库；保存精确数值的逐表副本、摘要、源原件及所需密钥。历史备份保留在原处，不递归打包进新备份。
3. 在隔离实例恢复备份，逐表比较记录数和内容摘要。归档可读取与实际恢复成功是两个独立结果。
4. 对每张来源表登记转换、历史保留、不恢复运行状态或待处理的去向。未经读取不能把未知数据域标为零；不能把归档当作已进入新业务账本。
5. 演练转换，并核对账号、分组、持仓、订单、现金、卡片、资料、素材、原件、设置、审计与客户端关联。
6. 正式切换前冻结业务写入和会产生外部动作的 Worker，重新捕获最终一致快照。准备阶段快照不能冒充最终切换快照。
7. 执行经过演练的转换，完成对账后切换；保留切换前的新库和来源库。无法证明提交结果时先查原回执，不重复导入。
8. 验证实际运行版本、登录、两步验证、关键业务数据、素材地址和重启后的状态，再恢复后台工作。PG 提交完成后才重建 Redis 缓存。

旧表结构转换与同结构整库恢复分别处理，不因两边都是 PostgreSQL 就直接覆盖新库。

## 数据边界

- 保留原账号登录身份、公开 UID、密码哈希、TOTP 秘密、最后使用步数和备用码哈希。通行密钥保留原始公钥字节、凭据 ID、RP 和计数器，不改写 RP 来绕过浏览器验证。
- 新库已有账号先完整备份。账号冲突、所有权映射及当前会话切换必须在执行计划中明确，不通过关闭 UID 保护触发器或把真实库改为测试环境来导入。
- 头像支持迁移原件，不能为满足旧的小图字段限制而静默缩小、扁平化动画或丢图。
- 历史订单原件、来源、金额及费用依据保持可追溯。缺少依据的值不升级为券商确认；当前持仓不倒推历史成交归属、开仓或费用。
- 自动生成的成交资金投影与独立资金记录分开核对，不能重复计入。仅用于参考的历史事件不追加现金。
- 待执行订单、过期会话、Worker 租约、未知投递结果和旧进程状态不会因恢复而自动执行。真实业务数据中不写入测试交易或测试通知。
- SQLite 和旧 Node PG 桥接定义仅作为来源归档保留，不重新接入运行时。

## 进度与动画

状态由后端已提交的阶段、任务回执和实际处理数量驱动。连接成功后点亮连线；执行中显示方向流动；已知总量时才显示已处理数量和比例。失败、中断、等待或完成后停止流动。动画不生成百分比，也不把客户端倒计时视为完成证据。

刷新和重新登录后通过原任务编号读取状态；页面不可见时停止轮询和动画。适配手机单列、深浅色及减少动态效果偏好。未完成的阶段不得显示完成标记。

## 当前实现边界

`database_migration_connections.py` 提供独立的旧库编辑、版本回执和只读连接检查。两边检查均绑定实际集群标识、库 OID、角色与 Schema；任务开始导出前重新核对，不能仅凭域名、库名或页面绿灯替代物理身份。运行绑定还包含构建提交、软件和驱动版本；更新后重新检查，原任务不能由不同构建续接。归档清单与回执保留实际构建和软件版本，未提供构建提交时明确为空。

`database_migration_jobs.py` 使用现有 Worker 和原请求 UUID 执行准备。每次尝试独立保存双库原生归档、精确数值副本、摘要和回执，不覆盖此前归档。`database_migration_rehearsal.py` 创建不监听 TCP 的临时 PG，用无超级权限、无建库和建角色权限的普通账号恢复两边归档，再逐表比较完整范围、记录数量与内容摘要。临时实例确认停止后才发布结果，成功后只清理该临时实例；失败尝试和备份继续保留。

页面支持历史记录、刷新续看、可见时轮询和取消。保存或任务受理结果未知时可查询原回执；取消操作保存持久标记，迟到的同编号请求不能再次执行，也不撤销已经提交的保存。准备结果为 `awaiting_mapping`，明确 `business_written=false`、`cutover_ready=false`、`files_included=false`：它证明双库归档和隔离恢复通过，未声称业务转换、原件及密钥迁入或正式切换完成。完整原件和密钥仍须随最终切换计划逐项核对。

失败记录的“重试未完成步骤”使用新请求编号保留原任务，通过原归档摘要与逐表副本重新核对后，只恢复未通过的部分。完整的旧库恢复回执可复用，已通过步骤不会重新导出或恢复；新的隔离实例只处理剩余库。原归档、原失败记录和原成功回执不覆盖，重试期间原文件变化即停止。重试重复请求查询同一任务，取消后的迟到请求不会重启；仍有运行任务、来源配置变化或原归档不完整时不受理，不把历史快照当作新采集数据。

现有身份导入器仍限隔离演练，支持核对头像原始字节；不能通过真实库改为测试环境来使用它。结构转换与正式执行尚不能仅凭准备成功开放。财务依据、来源归属及完整性缺失时保留差异，不能为完成迁移而静默补零、推断账户或重算旧记录。

## 转换与正式导入

双库恢复核对通过后显示“转换并校验”。此操作复用原归档和恢复证明，生成独立转换任务与带摘要的转换计划，不重新导出或恢复已通过的数据库。管理员明确来源账号、真实/模拟分类、原券商标识以及市场归属；断网或结果未知时查询同一请求，取消会保留持久标记，迟到请求不重启。

页面分别展示原始数量、规范化数量与待核对项。持仓与自选分开识别；历史盈亏保留来源登记值，不使用新成本算法覆盖；成交自动资金投影不会再作为独立资金入账。来源的实际费用、成交前后成本或港股通人民币结算缺失时，保留原数据与差异，不补零、不倒推券商、不从现价推算结算汇率。

转换计划生成后，映射完整的当前持仓、自选与券商分组显示“导入持仓与自选”。它按原始数量、成本与分组登记当前状态，历史状态标为未知；不重放历史成交、不推算费用或现金、不切换登录身份，也不宣称全部迁移完成。

导入时在来源记录、账户、分组上持有短期共享锁，逐表核对与归档一致，变化时拒绝旧快照。新库要求本人业务范围为空，所有原生业务操作、来源映射和不可变导入回执和任务完成状态在同一事务提交；中途异常整批回滚。提交回应丢失或 Worker 重入时只读取原回执，同一来源不能重复导入。迟到取消不能把已提交批次标为取消；历史不完整状态可依据不可变回执恢复为成功。备份与原归档保留；历史交易、资金、身份和原件仍须各自完成核对与迁入。

### 原始交易与资金历史

已完成持仓导入的同一转换记录由“完成剩余迁移”接续历史步骤。迁移任务复用账户、证券和来源编号映射，冻结并核对来源的完整财务表，归档清单或任一原行变化即停止。原始 PG 字段、费用依据、更正证据和资金流水在不可变历史批次内保存，与任务成功状态同事务提交；重复来源、迟到取消和响应丢失不会再次导入。不会重复创建账户或持仓。

当前持仓数量、成本保持不动；原始交易以登记历史进入订单和期间读取，原挂单保留为暂停状态，不生成新成交或再次扣款。独立资金调整保持原范围，不猜测券商；成交关联资金投影只保留原条目一次，不追加到现金账本。原盈亏是来源登记值，缺失费用仍未核对，不能冒称券商实付或完整账户回报。资金记录页面可读取已迁入的原始流水，实际可用现金仍由可核对的现行资金来源决定。身份、原件和正式切换分别核对，历史导入不把这些阶段标为完成。


### 完成剩余迁移

已完成持仓导入的原转换记录使用 `POST /api/fire/database-migration/conversions/{task_id}/complete`（规范路径同样提供）。一个后台任务依次执行新库完整 PG 归档与 Vault 原密钥备份、历史交易/资金、素材原件、个人数据、旧身份切换。源数据必须仍与封存副本一致；头像、两步验证和通行密钥的访问源、密钥在任何业务写入前预检。已完成的持仓、历史、素材逐项记录和个人批次按来源复用；失败只接续未完成项，不删除或覆盖原归档。

运行前在私有备份目录的 `migration-completion-input` 登记 `media-manifest.json` 与 `source-data.key`，目录 0700、文件 0600，属应用账号。清单包含与转换计划一致的 `source_instance`、`source_owner` 及原始 uploads 文件的 `path`、`bytes`、`sha256`；不接受网页文件地址或猜测同名文件。清单和身份密钥只在服务端使用，不放进公开源码、任务响应或浏览器。原件校验失败即停止；旧自定义卡片本就没有原件登记时，保留原卡片编号、资料和缺失引用并记录数量，不猜测替换图片。已删除的功能图标仅保留原归档，不重新启用。

个人数据保留 FIRE 规划、独立记账、活动、自定义卡片原编号、原卡面清单和卡包持有关系；提醒规则及动态分组、文章、讨论保留原值。历史动态的来源明确标为封存原行，不能冒充新采集页面。旧提醒授权、自动采集任务、发送队列、缓存、Worker 租约、旧 Web/App 会话与令牌不重新激活，原记录保存在完整 PG 归档中。删除的智能助手、全局资产配置等模块不恢复。券商、交易、资金仍遵守原值及未核对边界，不推导实际现金。

最后在一个事务内保存当前新账号的加密完整身份副本、恢复旧密码哈希/TOTP/通行密钥/个人资料、撤销新会话并完成任务。公开 UID 保持原值，内部账号 ID 通过已导入证券与账户映射继续归属本人；不改写所有者外键。原登录会话失效后页面显示旧账号登录入口。身份切换事务异常全部回滚，已完成业务阶段保留，失败状态继续显示真实已完成类别。数据库归档及原 Vault 密钥与原件目录共同组成恢复所需材料；不能仅凭一份 PG 文件声称图片已打包。

盈亏展示按来源登记值读取，不再用当前经济成本算法覆盖迁入历史。已登记盈亏与当前浮动盈亏可以按当前汇率展示；这不证明完整账户回报，缺少期初 NAV、历史现金与汇率时收益率及资产曲线保持未知。个人背景支持原 PG bytea，通行密钥时间支持原毫秒协议，原图和密钥内容不改变。
