# 邮箱注册与资料同步

注册支持两种标识：原用户名注册，以及先验证邮箱再创建账户的邮箱注册。邮箱流程由 native_login.email_registration 明确声明固定路径、6 位验证码、30 分钟时效、60 秒重发间隔和 5 次尝试上限；客户端不向未声明协议的服务猜测请求。邮件服务不可用时不声明邮箱注册可用，原用户名流程保持。

请求验证码只保存临时挑战、邮箱和码摘要，不保存密码、不创建用户或会话。验证码摘要包含随机 256 位挑战；数据库不保存原挑战或原码。错码计数提交后才返回失败；换邮箱、换源、过期、超额尝试和被替换的挑战都不能创建账户。旧邮箱与可注册邮箱使用相同请求回执，不向访客公开是否已有账户。SMTP 失败保留发送预算，撤销对应挑战，不自动重发。注册尝试与创建成功配额继续共享原服务端持久预算，邮件另沿既有收件人及全站预算。

最终提交在同一 IMMEDIATE 事务内完成：复核注册开关、验证挑战、核验邮箱唯一性、预留创建额度、创建普通账户、保存绑定邮箱及验证状态、建立会话、消费挑战。任一写入失败全部回滚。邮箱注册不能创建首个管理员。邮箱以独立公开用户名关联，避免个人资料或动态公开私人邮箱；数据库触发器约束所有新邮箱赋值，大小写及首尾空格归一化，保留既有记录而不猜测旧邮箱所有权。

修复 createUser 回执将邮箱写成空值的问题。邮箱注册回执、密码登录、Web 会话、v1/v2 me 和个人资料沿同一已验证邮箱。客户端只在绑定、已验证状态和账户身份全部吻合后完成注册衔接；不在客户端补造验证状态。

原生注册和忘记密码复用现有邮箱验证页面、共享六格验证码控件和安全输入。密码恢复仍使用独立挑战及恢复证明，不可用注册码或邮箱验证链接直接改密。邮件继续由同一品牌渲染器生成，注册新增独立用途模板；原四种模板的稳定 ID 与顺序保持，密码恢复沿原配置模板与品牌横幅。无外链注册或默认服务地址／凭据显示。

验证使用临时数据库、捕获的 SMTP 和隔离 App。覆盖真实路由、绑定回执、重新登录及两个版本资料读取、错误／过期／替换挑战、限额、唯一性、写入失败回滚和原生页面。真实邮箱投递不由隔离 SMTP 测试替代，未部署的协议不得声明线上已经可用。
