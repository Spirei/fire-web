# Fire 接口与配置迁移

Fire 统一承载网页、App 接入、原生业务后端和 Worker。当前采用 PostgreSQL，Redis 仅保存可重建缓存。未来可评估更合适的数据库；本轮不保留 SQLite 运行时、旧 Node PG 桥或数据库切换开关。

## 剩余 45 个入口

逐项决策保存在 `contracts/fire-api-decisions.json`：33 个保留原生实现，3 个安装包接口迁入，9 个退出。系统的接口迁移页依据实际方法和路径核对注册状态，不将动态路由、隐藏 OAuth 回调误记为未接入，也不以注册成功冒充页面或 App 验收。

- 原生通行密钥的四个注册占位接口退出，返回 404；实际网页注册保留，App 列表和删除保留，发现能力仍明确关闭原生注册。
- 旧 `/api/migration-export` 生产器退出，由现有联合备份服务统一提供 PG、原件和密钥封装的加密备份及持久任务回执。历史归档读取和校验能力保留，不删除用户已有文件。
- 旧开发版本轮询退出，开发环境使用框架热更新。
- 安装包列表、上传、下载迁入原生后端。元数据在 PG，原件在私有 SHA-256 存储，纳入联合备份；上传使用管理员网页会话、CSRF 和原请求 UUID，同 UUID 重试只接受相同内容。下载核验长度和摘要。只校验基本文件签名，不宣称安装包已通过平台签名或可安装性验证。

上游已经迁出的 3D 展示接口另列为退出，不混入上述 45 个基线。`platform/contracts/migration-register.json` 和 `api-capabilities.json` 记录历史来源与能力证据，不能作为 Fire 当前可调用入口清单；当前清单为 `contracts/fire-api-surface.json`。

## 主分支新增界面

个人主页资料与背景、账户请求活动、搜索历史、素材目录和管理员通行密钥列表的 10 项方法一起迁入内置后端，沿用已有页面。搜索记录存 PG，按当前账号隔离并用版本校验处理清空、延迟写入和多设备冲突；素材批量移除、恢复、分类与排序沿用现有公共目录事务，UUID 回执与版本校验一致，名称与券商分类一起提交，不读取行情。

## 配置与上线

PG 与 Redis 连接由环境配置统一提供，管理页只读展示脱敏配置并检测实际连接，不再保存第二套连接目标。参见 `.env.example` 与 [部署说明](synology-deploy.md)。`platform:inspect` 只读核对库中 UUID；启动不初始化、不迁移、不创建替代库。无标识且非空的旧库必须先完成来源核对与迁移，不能通过新填 UUID 绕过。

文档中早期 Node/SQLite 实现、临时测试结果和已删除的 Node 测试文件引用属于历史记录。当前安全与业务验证使用 `platform/tests` 下的隔离 PostgreSQL 回归，网页交互验证在 `tests`。旧导出格式、交易来源和历史证据仍用于只读导入核对，不是在线 SQLite 兼容层。

冒烟使用独立实例预置账号及 `SMOKE_ACCOUNT_FILE`；移除旧 HTTP 自动注册测试账号的工具分支，既有账号凭据不会自动覆盖。隔离实例可显式设置 `SMOKE_PROVIDERS=0` 只读巡检页面与已配置服务，外部行情、公开内容及汇率单列跳过，不以测试值代替真实来源；默认仍检查真实来源。

源码推送、镜像发布、容器替换、真实数据迁移和网页/App 联调分别验收。源码与合成测试通过不表示生产数据已迁入或线上版本已更新。
