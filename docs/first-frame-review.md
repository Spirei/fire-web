# 全站刷新首屏排查（2026-10-01）

首屏视图必须来自当前 URL、服务端设置或服务端注入的偏好。`useLayoutEffect` 只能修正浏览器绘制前的状态，不能修改浏览器已经收到并显示的服务端 HTML；因此仅把 `useEffect` 换成 `useLayoutEffect` 无法消除默认页面闪现。

## 本轮修复

| 页面 | 首屏状态来源及修复 |
| --- | --- |
| 请求日志、独立 API 请求页 | 页签已有 URL 首屏逻辑；本轮补齐查询、日期范围、年份和分页筛选，不先显示默认筛选。路径里的 `vN` 配色继续使用统一动态版本组件。 |
| 全球经济、汇率换算 | 从 URL 读取功能、输入币种和金额；换算表参与服务端渲染，无报价币种保留“暂无汇率”。 |
| 素材库 | URL 分类、市场、查询、排序、分页及布局进入首屏；非默认筛选不显示默认股票快照；卡片未读取完成时显示加载态，不显示假空列表。 |
| 附件管理 | 分类与财报目录直接按 URL 渲染，目录解析兼容损坏编码和无效年份。 |
| 财报日历 | 市场与股票类型按 URL 首屏选中。时间/市值偏好沿用原 Cookie 镜像。 |
| 我的持仓、自选股、个股详情 | 市场和直达标的首屏生效；详情页签直接恢复，收藏状态使用已知关注状态；兼容含点股票代码；持仓排序及市场盈亏卡片顺序镜像原本地偏好。 |
| 设置 | 分类、来源与详情锚点按 URL 渲染，去掉等待挂载的整页空壳；详情弹窗在服务端直接渲染，挂载后移到 body，保持原关闭和层级逻辑。 |
| 通用弹窗 | 服务端与客户端初始均渲染同一内容，挂载后使用 portal；避免直达通行密钥等设置时访问不存在的 document。 |
| 资产分析、资产总盈亏 | 两页使用同一 Cookie 镜像的日历市场、年月、视图和指标；资产分析模块顺序直接下发服务端设置。 |
| 名人持仓 | 当前启用人物与已有数据快照从服务端读取，不启动外部查询、不在快照函数补种数据；首屏直接展示指定人物，服务端快照不被旧浏览器缓存覆盖；列设置镜像原偏好；收益图使用稳定 SVG ID，修复随机 ID 的水合差异。 |
| K 线 | 原有周期、时段、分钟及图形/指标设置镜像至 Cookie，首屏读取校验后的保存值。 |
| 简化 App | 在页面绘制前应用独立主题和窗口宽度；全站主题在该路由暂不覆盖独立主题，离开后恢复全站选择。 |

其余主页面延续现有服务端快照、URL 或 `usePersistedState` 流程。用户管理和实时行情等异步数据仍使用加载状态；取得新行情后的正常价格更新不属于默认视图闪现。本轮未改动首页 3D 渲染及模型切换链路。

## 验证

- `tests/first-frame.cjs` 的 12 组隔离回归直接检查未运行浏览器副作用的服务端 HTML，包括错误参数、非默认筛选、自定义名人、弹窗和保存的图表/日历设置；名人快照检查不补种数据。仅屏蔽与导航无关的密码 Worker；Next dynamic 用测试占位，真实路由另外构建及浏览器验证。
- `npm run test:review` 运行全套隔离回归，`npx tsc --noEmit`、`npm run build` 与 `git diff --check` 检查实现与服务端编译。
- 独立测试账号只读巡检 59 项通过，未修改真实用户业务数据。
- 用户 Chrome 实测刷新首屏：汇率换算、设置分类及外观详情弹窗、财报日历筛选、报告目录、素材分类/布局、持仓市场与名人详情；请求日志继续专项复查。浏览器控制台检查水合错误。

## 兼容及范围

保留已有 URL、存储键和业务数据。旧用户只有 localStorage 的偏好会在第一次进入对应页面时镜像至 Cookie；该次恢复仍可能有一次调整，此后刷新读取服务端镜像。Cookie 有既有 3000 字节预算，过长偏好继续按原机制从本地恢复；未承诺存储被禁用或 Cookie 被清空时仍能恢复服务端不可见的偏好。

异步实时数据、图片与浏览器专属装饰按原加载方式显示。本轮覆盖桌面 Chrome 和服务端回归，不等同于实体手机/全部浏览器的逐帧测试。
