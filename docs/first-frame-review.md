# 全站刷新首屏排查（2026-10-01）

首屏视图必须来自当前 URL、服务端设置或服务端注入的偏好。`useLayoutEffect` 只能修正浏览器绘制前的状态，不能修改浏览器已经收到并显示的服务端 HTML；因此仅把 `useEffect` 换成 `useLayoutEffect` 无法消除默认页面闪现。

## 本轮修复

| 页面 | 首屏状态来源及修复 |
| --- | --- |
| 请求日志、独立 API 请求页 | 页签已有 URL 首屏逻辑；本轮补齐查询、日期范围、年份和分页筛选，不先显示默认筛选。路径里的 `vN` 配色继续使用统一动态版本组件。 |

| 素材库 | URL 分类、市场、查询、排序、分页及布局进入首屏；非默认筛选不显示默认股票快照；卡片未读取完成时显示加载态，不显示假空列表。 |

其余主页面延续现有服务端快照、URL 或 `usePersistedState` 流程。用户管理和实时行情等异步数据仍使用加载状态；取得新行情后的正常价格更新不属于默认视图闪现。本轮未改动首页 3D 渲染及模型切换链路。

## 兼容及范围

保留已有 URL、存储键和业务数据。旧用户只有 localStorage 的偏好会在第一次进入对应页面时镜像至 Cookie；该次恢复仍可能有一次调整，此后刷新读取服务端镜像。Cookie 有既有 3000 字节预算，过长偏好继续按原机制从本地恢复；未承诺存储被禁用或 Cookie 被清空时仍能恢复服务端不可见的偏好。

异步实时数据、图片与浏览器专属装饰按原加载方式显示。本轮覆盖桌面 Chrome 和服务端回归，不等同于实体手机/全部浏览器的逐帧测试。

## 工作区切换及四色门复查（2026-10-02）

复查了 10 月 1 日的更新记录及 `7b004d8`（首屏状态）、`43844d8`（请求日志）等相关修改。以下修复仅针对后台加载、缓存页布局和地址状态，不修改首页、账户资产排版、财务计算、用户数据或已有偏好。

- **第一次打开页面留白**：后台 16 个动态页面此前没有下载中的反馈。现在仅在目标页代码尚未到达时显示局部静态占位，已打开的页面继续直接显示；每个页面独立处理渲染/代码加载错误，明确提供重新加载，不让单页异常变成整个后台白屏。
- **隐藏页布局风险**：旧规则在支持 `content-visibility` 的浏览器中把 `hidden` 覆盖为 `display:block`，再以零高限制占位。移除该特殊分支，统一使用 `display:none !important`。React 组件继续挂载，筛选及滚动记忆保留，但隐藏页没有布局盒。当前本地 Chromium 未稳定复现旧版日志落到最下方的现象，不能将其断言为唯一根因；修复后实际切换中隐藏盒高度始终为零，日志工作区正常位于顶部。
- **缓存页串用地址状态**：隐藏的组件仍会收到全站 `useSearchParams` 更新，部分页同时监听 `popstate` 或自动规范化地址。现在每页保留自己的参数快照，原生监听器与 URL 同步必须检查当前页身份和真实路径；还处理了代码下载完成时用户已切走的首次挂载，不拿当前其他页面的参数初始化。卡面漫游、设置、持仓、自选、财报、素材、附件、请求日志及汇率换算一并检查。
- **四色门下载串行**：原来交互代码采用 `ssr:false` 加空白回退，插图必须等代码到达后才开始请求。改为同风格静态预览与交互代码并行加载，复用原图片地址和样式 2 的矢量图，保留选中方向及样式偏好；装饰加载失败只回退静态图，侧栏其他入口仍可用。非平板、宽度至少 1280、高度至少 801、主输入可悬停且精细指针的原挂载条件不变，手机、平板及短屏不通过预览额外下载图片。服务端仍不能可靠知道浏览器实际窗口和主输入，装饰在水合识别后才显示，未承诺完全零等待。

验证包括 15 组隔离首屏回归（含真实静态预览、错误边界、缓存参数及延迟隐藏挂载），全套 `test:review`、类型检查和独立测试账号只读巡检 59 项。浏览器检查覆盖连续切页、前进后退、请求日志和多页缓存；1440×1000 下工作区顶端为 128px，1280×720、1024×768、768×1024、390×844 下隐藏页无占位且无四色门图片元素。首个设置页实际显示局部加载反馈，随后正常到达；控制台没有新增水合/运行错误。视口测试不等同于实体 iPad、Windows 或 Safari 验证。

同日追加：设置 → 外观新增个人偏好 `fire:four-door-enabled`，默认关闭，沿用 localStorage 与 Cookie 镜像。关闭时整个四色门子树不挂载，移除空白占位；静态预览也改为 `React.lazy`，开启且符合原设备条件时才触发预览与交互模块下载，图片和音效随组件生命周期管理。首屏回归扩展到 17 组：核对开关默认与保存值，并在模拟符合条件的桌面上确认关闭时两个 lazy 加载入口均未执行，开启时均执行，不符合条件时继续不执行。该资源入口回归使用隔离渲染，不代替浏览器网络面板实测。

生产分包复核：预览与交互的图片引用只出现在两个独立异步分包中，外观设置和后台布局分包不包含这些引用，`app-build-manifest.json` 的默认页面加载清单也不包含这两个分包。关闭状态没有触发下载的入口。浏览器控制连接超时，本次没有补充网络面板实测。

## 继续排查（2026-10-02）

- 布局的偏好快照可能早于同一会话里的用户操作。`usePersistedState` 区分服务端水合与随后新挂载：水合保持原 HTML 对应的快照，客户端新挂载直接读取当前 localStorage／Cookie，不等副作用再恢复。包含存储受限、清空偏好和旧字符串兼容回归。
- 请求日志与独立请求页的筛选直接来自 URL；每份结果带上自己的查询标识，筛选改变的第一帧不显示前一次行、统计或趋势，晚到的旧响应不能覆盖当前条件。正常实时更新保留同一查询下的结果。
- 全球经济区块与汇率输入不再通过挂载时快照和自动回写维护地址；用户操作写入地址，前进后退直接读取当前参数。输入草稿仅对应自己的地址，保留清空金额与小数输入行为。
- 请求日志、请求页及文档的 `vN` 配色由根布局加载，缓存页面不会拥有全局样式的生命周期。
- FIRE 仍需要读取旧本地规划与业务配置；恢复时显示「正在恢复退休规划」，不再给用户一片无说明的空白。未修改规划计算或持仓数据。

新增保留 Hook 状态的隔离检查，刻意不运行 effect，核对地址变化后的第一个渲染结果。它补充 SSR 回归，不代替浏览器逐帧视频和实体设备验证。
