# 本地开发服务恢复（2026-10-05）

开发服务固定由 PM2 的 `fire` 运行，工作目录为 `fire-web`，监听 `0.0.0.0:3000`。

此次无响应的复现条件是启动后约30秒，惰性自动备份开始向外部卷复制整个 uploads。原来的4路复制占满 Node 默认文件线程池，Next 页面编译和文件读取也在等待同一线程池；直接重启只能短暂恢复。旧快照同步遍历目录也可能在慢盘上阻塞 JavaScript 主线程。

修复已落在 `lib/backup.ts`：

- 素材单路复制，保留清理也逐项异步删除，避免 Node 内置递归 rm 再次并行占满线程；为页面编译和文件读取保留其他线程；备份内容、在线SQLite快照与保留策略保持。
- 同一数据目录的任务、节流和当前快照状态在开发模块/热更新之间共享，避免重复备份。
- 旧快照的目录统计使用异步文件操作；备份索引仍优先读取，不在请求中同步扫描大目录。
- 失败时等待复制结束，再移除本次未完成的目录；保留完成快照和下一次重试能力。

本机已停止旧进程并重新生成损坏的开发缓存；PM2仅保留工作目录正确的 `fire`，移除了3个目录错误的历史注册并执行 `pm2 save`。不要另行运行第二个 `npm run dev` 抢占3000端口。

日常操作：

```sh
pm2 restart fire
pm2 logs fire --lines 40
curl --max-time 10 -I http://localhost:3000/login
```

如必须重建开发缓存，先 `pm2 stop fire`，确认3000监听已释放，再删除可再生成的 `.next-dev`，然后 `pm2 start fire`。不要在守护进程仍会自动拉起时删除正在使用的缓存。

验证：`node tests/backup-runtime.cjs` 使用临时目录模拟慢复制、模块重载、无索引的旧快照扫描与失败重试；`npm run smoke` 使用独立账号只读验证页面和权限，不写真实业务数据。
