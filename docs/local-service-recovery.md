# Fire 本地启动与恢复

网页和内置业务后端由 Fire 的同一启动命令管理。当前使用 PostgreSQL，Redis 可选，后台 Worker 按需独立运行。数据库故障时不会回退 SQLite，也不会创建替代空库。

先核实私有配置及目标实例，再按照根目录 README 安装 Node 与 Python 依赖。开发和生产均可配置端口；已有端口被占用时选择可用端口，不停止其他项目的服务。

```sh
npm run dev -- --port 3001
npm run build
npm start -- --port 3001
```

环境配置可通过进程环境或未提交的 `.env.local` 提供。`FIRE_PUBLIC_ORIGIN` 必须对应实际访问地址及端口；`FIRE_PYTHON` 指向安装了内置后端依赖的 Python。使用进程管理工具时，工作目录必须是 Fire 仓库根目录，并运行 `npm start`。

启动命令会核对数据库身份和迁移版本，再启动网页；它不执行生产库初始化或数据导入。通过 `/health/ready` 与系统总览核实当前状态。启动失败应根据实际错误修复配置、身份或迁移状态，保留原始数据与备份。

只清理本次启动创建的临时 socket 和进程。不要删除用户数据、替换他人服务或将构建通过当作线上已更新。
