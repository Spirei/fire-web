# 邮件安全审计 · 2026-09-27

范围：忘记密码验证码、邮箱确认链接、管理员测试邮件及 SMTP 出口。邮箱与 TOTP 仍为独立找回方式，本次不改变验证策略。

## 发现与修复

- 原忘记密码只有账号 60 秒冷却，缺少持续骚扰的小时/每日上限；原确认邮件和测试接口按 IP 与账号组合计数，换 IP 可获得新桶。现增加实际 SMTP 出口额度，并将 IP 与账号请求额度分开。
- 邮件预算由 SQLite 即时事务串行准入，跨进程共享、重启保留，不随 `RATE_LIMIT_STORE=memory` 退回内存。存储异常停止发信，不自动重试 SMTP；失败/超时仍计一次尝试。
- 准入与生成验证码/确认链接在同一事务中完成。超额或存储异常不替换用户现有凭证；内部发信许可为进程内不可伪造的一次性对象，不能通过 HTTP 提交绕过额度。
- 只允许一个纯邮箱收件人，拒绝地址列表、显示名及换行输入，避免 Nodemailer 解析为多个收件人。测试失败返回通用错误，不回显 SMTP 内部信息。
- SMTP 统一要求 TLS：465 直接 TLS，非直接 TLS 必须完成 STARTTLS，最低 TLS 1.2 并验证证书，不允许静默明文降级。禁用邮件内容从本地文件/外部 URL 读取；不支持 TLS 或使用不可信证书的邮件服务器将发送失败，需修正服务端配置。
- 公开找回响应保持中性，不因收件人额度用完而暴露账号；已登录本人可得到简短限流提示。无邮箱或未验证邮箱不发送找回邮件，不能任意指定收件人。

## 实际发信尝试额度

全部为滑动窗口，不在整点/午夜重置；超额不进入 SMTP。失败也占用额度。

| 范围 | 额度 |
| --- | --- |
| 同一邮箱，所有类型合计 | 60 秒 1 次、1 小时 8 次、24 小时 20 次 |
| 同一邮箱，忘记密码 | 1 小时 3 次、24 小时 10 次 |
| 同一邮箱，邮箱确认 | 1 小时 5 次、24 小时 10 次 |
| 同一邮箱，测试邮件 | 1 小时 3 次 |
| 全站，所有类型合计 | 1 小时 100 次、24 小时 500 次 |

额度记录只存邮箱 SHA-256 摘要、类型和时间，不存验证码、SMTP 授权码或明文收件地址。成功准入时清理 24 小时前记录。额度达到上限不锁定账号，登录及 TOTP 找回仍可使用。

## 验证与部署边界

隔离数据库和模拟 SMTP 覆盖：滑动窗口、小时/24 小时边界、大小写变换、跨邮件类型、全站额度、失败不退额度、额度拒绝不覆盖凭证、许可防复用/伪造、数据库故障停止发信。4 个并发 worker 对同一邮箱发起 160 次调用，只准入一次。

本次未发送真实邮件。持久化预算要求应用实例共享同一个 SQLite 数据库；独立数据库的多副本不能共享额度，应改用共享预算存储或邮件网关限额。可信代理必须覆盖客户端转发头，不能直接信任任意 `X-Forwarded-For`。全站上限可能在分布式攻击时暂时阻止合法发信，这是保护 SMTP 额度的保守选择；大规模部署应再加边缘机器人防护和供应商告警，而非声称应用限流能消除所有攻击。
