# 模型服务配置

网站与 App 的模型请求统一由服务端执行。管理员可管理服务；普通账户只获取模型名称、顺序与连接状态，不接收 API 密钥。管理员接口也只返回密钥是否已配置。

- 密钥按服务 ID、提供方及完整 API 地址隔离。留空保留同一配置的已有密钥；不同服务、提供方或地址不会继承其他密钥。修改地址会清空当前输入的密钥；已配置地址的变更须提供新地址密钥，否则拒绝保存并保留原配置；保存后的响应、取消编辑及关闭助手配置会清除未保存的密钥输入。
- 公网模型接口须使用 HTTPS。显式配置的 localhost、内网 IP 网关允许 HTTP；带密钥的请求不跟随重定向。恢复默认配置保留同一地址的密钥。
- 保存 `modelServices` 或上传模型图标须带 `/api/settings` 返回的 `modelServicesRevision`。缺少版本返回 428，版本冲突返回 409，本次修改不覆盖服务器的新配置。冲突后保留草稿，刷新核对后重新编辑。
- 设置写入使用数据库事务。模型 ID 重复、字段超限或不安全的地址会拒绝保存，不截断密钥或悄悄改写服务 ID。删除所有服务后不恢复旧模型；删除最后一个模型后服务保留为待完善状态。
- 草稿连接测试只影响当前页面。仅当提供方、地址、密钥和模型仍与已保存配置一致时，测试结果才更新正式模型状态。上游响应正文及密钥不会包含在错误返回中。

## 备份与恢复

服务端使用 AES-256-GCM 加密存储密钥。备份数据库时必须同时保留原有 `FIRE_ENCRYPTION_KEY`，或未设置该环境变量时的 `data/.fire-encryption-key` 文件。密钥文件权限为 0600，不随仓库提交，也不下发到 App。恢复时必须使用原有加密密钥；损坏密文或错误的加密密钥会停用模型调用并阻止覆盖配置，管理员会收到恢复提示；网站其他功能保持可用，原始记录保留，避免以空密钥覆盖已有设置。
