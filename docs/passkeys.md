# 通行密钥（Passkey）

管理员在 **设置 → 账号 → 通行密钥 → 登录设置** 填写线上完整 HTTPS 地址（如 `https://fire.example.com`）及站点名称，启用后点击「保存」，在弹窗输入当前密码；已启用 TOTP 时还需验证码或备用码。页面中的「取消」还原编辑，弹窗中的「取消」保留编辑。配置保存于该部署的数据库，其他部署使用自己的域名，不需要修改源码或申请苹果开发者账号。

用户通过配置的 HTTPS 地址登录后，在「我的通行密钥」点击「添加密钥」，在弹窗填写名称（选填）、当前密码及已开启的二次验证码。由浏览器选择保存位置：iCloud 钥匙串、Bitwarden、1Password、Google 密码管理器或支持可发现凭据与用户验证的安全密钥。同步由对应系统或密码管理器负责，Fire 不接触私钥、设备 PIN 或生物识别数据。具体选择界面由操作系统、浏览器及密码管理器版本决定。

之后登录页点击“通行密钥登录”，选择账号并完成 Face ID、Touch ID、PIN 或密码管理器解锁。此方式要求 WebAuthn 的 user verification，替代密码加 TOTP；密码登录仍遵循原有 TOTP 策略。

## 域名与部署

- RP ID 自动取配置地址的完整主机名，不开放任意父域或通配域名。端口属于 Origin 校验的一部分。
- 反向代理应保留正确的 Host；HTTPS 登录 Cookie 根据已核验的配置 Origin 设置 Secure，不依赖请求提供的代理协议头。
- HTTP 局域网 IP 不支持通行密钥；开发测试仅允许 `http://localhost:3000` 等 localhost 地址。
- 更换域名时旧域名的密钥无法在新域名使用；先保留密码登录，再在新域名重新添加。关闭功能不会删除现有密钥，恢复原配置后可继续使用。
- 更换主机名需重新添加密钥，仅调整同一主机名的 HTTPS 端口或站点名称不改变密钥归属；仍须通过配置的完整 Origin 使用。
- 实际变更配置会撤销正在进行的挑战；内容不变的保存保留挑战。网页保存带配置版本，旧窗口编辑会收到冲突提示，防止覆盖其他窗口的新设置。每个账号最多 20 个密钥。
- 地址在身份验证之前校验，无效地址不消费 TOTP 或备用码。网页请求有超时限制；保存、删除等结果未确认时，先点「刷新确认」核对实际状态，编辑内容仍保留，再决定是否操作。

## 恢复与安全

删除密钥会在同一事务中撤销通过该密钥创建的所有会话（包括当前会话），已撤销会话不能续期。其他密钥和密码创建的新会话不受影响。升级前会话没有登录来源信息，因此删除密钥时会保守退出该账号全部来源不明的旧会话，不影响其他账号。当前会话被撤销后页面会返回登录页；删除接口返回 `signedOut` 标记。

登录挑战签发按服务端签名的浏览器标识限流（30 次/15 分钟），每个浏览器只保留最新登录挑战，多标签同时登录需重新开始。配置可信反向代理时另加每 IP 100 次/分钟的签发限制；没有可靠客户端 IP 时不把所有人归入共享桶。注册使用独立账号额度，验证依靠五分钟、一次性、绑定浏览器的挑战，不共享签发限额，避免一个来源锁住全站登录。

浏览器 Cookie 限额不是抗洪泛边界：攻击者可以丢弃 Cookie 重新申请。公网部署必须在反向代理/网关对该路径设置按真实来源的速率和连接限制，不能直接暴露源站绕过代理；只有代理覆盖并清洗转发头后才能启用 `FIRE_TRUST_PROXY_HEADERS=true`。多 IP 洪泛仍需网关防护，不以全站 15 分钟硬锁代替。

添加和删除密钥、修改站点配置必须重新验证密码及已启用的 TOTP。只有密钥所有者能读取其列表、改名或删除。管理员重置密码作为账号恢复操作，会同时撤销该用户的 TOTP、全部通行密钥、登录会话和注册挑战；用户自行正常改密保留已有通行密钥。

数据库仅保存公钥、随机账号句柄、签名计数器、传输方式、同步备份状态及时间。挑战绑定 HttpOnly / SameSite=Strict Cookie，注册挑战另绑定当前会话与密码版本；五分钟过期，使用时原子消费。签名校验强制要求用户验证，验证 Origin、RP ID、账号句柄、挑战及计数器；兼容同步通行密钥返回零计数器的行为。

备份整份数据库会包含通行密钥配置和公钥；个人数据导入/导出不含认证凭据，不能借导入修改绑定或域名。

## 验证

`npm run test:passkeys` 使用临时数据库、真实 ES256 密钥对和 CBOR 认证数据，覆盖注册、无用户名登录、挑战重放、错误域名/签名/账号、缺少用户验证、会话绑定和账号恢复。`npm run test:review` 包含这些用例。实际 iCloud 同步及第三方密码管理器界面需在部署的 HTTPS 域名和对应设备上由用户完成绑定验证。

实现参考：[SimpleWebAuthn 服务端文档](https://simplewebauthn.dev/docs/packages/server) 与 [浏览器文档](https://simplewebauthn.dev/docs/packages/browser)。

验证代码在页面加载时随组件准备，点击后仅请求验证参数再调用浏览器验证，避免旧版 Safari 在点击中额外异步加载代码丢失用户手势。离开页面会终止请求与尚未完成的浏览器验证。兼容依据见 [Safari 浏览器差异](https://simplewebauthn.dev/docs/advanced/browser-quirks)。
