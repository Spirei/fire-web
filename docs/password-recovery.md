# 邮箱确认与密码找回

入口：登录页「忘记密码」、设置「更改密码 → 找回密码」、`/reset-password`。

邮箱确认：登录后在个人信息保存邮箱，向 `/api/auth/email-verification/request` 发送 POST。邮件内含 30 分钟有效的确认链接，`/verify-email` 页面向 `/api/auth/email-verification/confirm` 提交一次性令牌。确认仅标记邮箱已验证，不修改密码。新邮箱与已有未验证邮箱都需确认；更改邮箱使旧确认与恢复凭证失效。

密码找回可任选一种方式，邮箱与 TOTP 不叠加：

公开入口默认邮箱，仅以“已配置验证器？改用验证器”提供替代入口，不并列展示两个必填步骤。已登录且未配置 TOTP 的账号只显示邮箱方式；已配置的账号优先验证器，仍可改用已验证邮箱。公开入口不查询或暴露账号是否配置 TOTP。

1. `POST /api/auth/password-reset/request`，提交 `login`（用户名或绑定邮箱）、`method`（`email` 或 `totp`）及可选的上一次 `challenge`。公开响应统一包含随机 `challenge`、`retryAfter: 60` 和中性提示，不返回验证码。邮箱路径仅发往已验证邮箱，SMTP 在响应后发送；本人已登录的请求可收到配置或发送错误。TOTP 路径不发送邮件，只允许已配置验证器的账号。
2. `POST /api/auth/password-reset/verify`，提交 `method`、`challenge` 和 `code`（邮箱六位验证码，或 TOTP/备用码）。成功返回短期重置 `token`，仅允许改密码，不产生登录会话。TOTP 消费与凭证签发在同一事务内，防止重放。
3. `POST /api/auth/password-reset/confirm`，提交 `token`、`newPassword`；不再额外要求另一种验证。后端检查凭证路径的有效状态，不信任前端声明。

邮箱验证码有效30分钟，TOTP挑战和重置凭证有效5分钟、只能成功使用一次。每账号每路径 60 秒冷却，验证最多 5 次错误尝试，并叠加 IP/全局限流。尝试耗尽只使本次恢复凭证失效，不锁定账号。邮箱重发使旧验证码和旧重置凭证无效。

数据库仅保留令牌摘要。验证码摘要结合未存明文的随机 challenge，凭证绑定密码摘要与邮箱快照；TOTP 路径还绑定验证器密钥。密码、邮箱或对应验证器改变后失效。密码更新、凭证删除及旧登录会话撤销在一个事务中，失败回滚。TOTP 配置保留，不因邮箱找回而关闭。已配置 TOTP 的用户仍可独立通过已验证邮箱恢复，这是产品明确选择的恢复策略，邮箱安全同样重要。

页面不把验证码/重置凭证放 URL、localStorage 或 cookie；刷新或关闭后需重新开始。旧链接不再使用，请重新申请。邮件验证码不放在标题中，无重置链接。日志不输出验证码或 SMTP 授权码。

测试：`npm run test:review` 使用临时数据库和模拟邮件传输，验证邮箱链接一次性确认、未验证邮箱不可恢复、冷却、过期、五次上限、重发失效、快照绑定、两路径独立、TOTP 防重放、备用码消费与会话撤销，不发送真实邮件。
