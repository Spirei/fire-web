# 网页登录有效期与续期

## 排查结论（2026-09-26）

旧代码的 `fire_session` Cookie Max-Age 与 SQLite `sessions.expires_at` 都固定为登录后 7 天（604800 秒）。普通读取不会续期，持续使用的账户同样在第七天失效。只读统计发现数据库保留了过期会话，但没有浏览器掉线时的请求与 Cookie 记录，因此不能把所有掉线都归因于该机制。

Cookie 为 host-only：localhost、局域网 IP、正式域名相互不共享。清除浏览器站点数据、主动退出、改密/开启二次验证撤销其他会话，也会要求重新登录；这些安全行为保留。生产服务仍会禁用默认 demo 密码，不放宽此保护。

## 新行为

- `UserMenu.tsx` 在挂载、回到可见页面/窗口及可见页面每 15 分钟通过 POST `/api/auth/me` 检查。焦点事件一分钟节流，同一组件不并发请求，卸载清理计时器和请求。
- `auth.ts` 对仍有效的 Cookie 会话最多每天续期一次，SQL 条件更新后同时设置新的七天 Cookie。退出或过期的令牌不能恢复。停止使用后的实际剩余时间通常约六至七天，而不是永久登录。
- POST 校验同源；GET `/api/auth/me` 不续期，Bearer 移动端保留原有固定有效期与接口兼容性。
- 网络失败不主动跳登录页；确认 401 后沿用已有登录处理。
- 现有未过期会话无须重新登录；已经过期的会话必须重新认证。

## 回归

隔离数据库模拟时间推进，验证双端期限、原到期日后仍有效、一天内不重复写入、GET 不续期、跨站拒绝、精确过期边界、撤销不可恢复及 Bearer 不变。所有写入测试均不使用真实账户库。
