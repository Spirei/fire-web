# 3D 展示台（Showcase）——换车 / 换素材指南

首页是一台滚动叙事的 3D 展示台。**引擎只认配置**，换车不用改引擎与组件。
日常加车走**导入向导**（首页右下角车型条末尾的「＋」），不需要改代码、不需要重新发版；
下面第一节是导入向导，后面几节是引擎 / 预设层面的做法（要加一辆随仓库分发的内置车时才用）。

## 文件结构

| 文件 | 作用 |
| --- | --- |

| `components/showcase/ShowcaseStage.tsx` | React 舞台：渲染 HUD（水印/章节/遥测/按钮/部件标注），挂载后才动态加载 three.js 与引擎 |
| `components/showcase/HomeShowcase.tsx` | 首页外壳：车型清单、按需加载（悬停预热 / 就绪后再切）、右下角车型条 |

| `components/showcase/presets/mcl35m.ts` | 迈凯伦 MCL35M 的预设（模型、镜头、配色、文案），也是导入车型复用的那套「与车型无关」的模板 |

## 上线一台新车：导入向导（推荐）

以**管理员**登录后，在首页右下角车型条末尾点「＋」，或直接开 `/showcase/import`（普通用户看不到入口、接口也会 403）：

1. **选文件**：拖入单个 `.glb`（≤ 250MB）。只放模型文件，贴图要已经打进 glb。体检文件仅写系统临时目录，请求结束即删除；工作台通过当前页面的 Blob 预览，不保存附件，也不写浏览器模型缓存。
2. **体检报告**：服务端会列出导出器、顶点 / 三角面 / 节点 / 网格 / 材质 / 贴图数量与最大贴图尺寸，并给出建议；外链缓冲区或贴图会被拒收，非三角图元、超高面数和超多节点会明确提示；
   Draco / Meshopt / KTX2 压缩过的模型会被直接拒收并给改法（导入前先在 Blender 里导出成未压缩的 glb）。
3. **独立模型调校工作台**：进入改参数后打开全屏工作区，顶部常驻保存与返回。左侧大画布使用模型展示同款探索镜头；整体、车身、尾翼、轮组、座舱使用不同颜色的三维投影点，随模型环视和缩放贴在对应部位。单击标注点或真实网格选择参数大类，所选大类保留彩色线框、其余网格使用纯线框模式同款浅灰；双击具体零件会在镜头聚焦的同时下钻到单个网格。右侧独立滚动，可修改车长、朝向、轮子、贴图及尾翼线框算法；共面三角边清理与折角阈值可为每台车单独保存。停止输入 350 毫秒后自动重建预览。
   新车型取消、离开或保存失败都会释放临时附件，重新进入需再次选文件。已保存车型的未保存参数、轮子选择和面板状态可暂存浏览器，返回清单后可继续调校。
4. **保存并上线**：只有预览成功且当前参数已经重载确认时才能保存；重新提交原始附件与参数，通过体检后写入模型文件与 `public/uploads/mclaren/showroom.json`；登记表保存失败时回收新文件。保存成功才保留附件并加入首页车型条，后续修改走同一车型的更新接口。

之后的日常调整都在导入页的卡片上：**改参数**（不用重新上传，改完再存一次）、**传封面 / 换封面 / 去封面**、
**移出清单**（保留上传的 glb，并记录到忽略清单，刷新不会自动复活）、**删除并删文件**（连 glb 一起删，注意会同时把卡片移出清单）、
**拖动左上角的 ⠿ 排序**（顺序就是首页右下角车型条的顺序，拖完立即保存）。

素材与登记表都在 uploads 卷里，**不进 Git、不进镜像**：换车 / 调参数不用改代码、不用重新发版；
往 `public/uploads/mclaren/models/` 直接丢 `.glb`（scp / docker cp 都行）也会自动出现在导入页里等人调参数。
封面是卡面上的照片，最长边建议 1600px 左右、单张 ≤ 6MB（PNG / JPG / WEBP）。

## 换一辆随仓库分发的内置车：四步（要改代码）

1. **放素材**：小于 100MB 的模型可以随仓库分发：放进 `public/<你的目录>/`（HDR 可用 Poly Haven 的 CC0 资源）；
   超过 100MB 的（GitHub 单文件上限）放 `public/uploads/mclaren/models/`，靠导入向导管理。
2. **复制预设**：复制 `presets/mcl35m.ts` 为 `presets/<你的车>.ts`，改 `assets`、`watermark` 与文案。
3. **对朝向与轮子**：
   - 模型朝向不对：调 `model.yaw`（绕 Y 轴，度）或 `model.pitch`（绕 X 轴，度）；
   - 轮子材质名不同：改 `model.wheelPattern`（正则源码字符串，不区分大小写）与 `wheelAxis` / `wheelLateral` / `wheelLongitudinal` 三个轴；
   - 没有独立轮子（例如整体一个网格）：把 `wheelPattern` 设成不会命中的字符串即可，轮胎就不会自转；
   - 材质太亮/太暗：用 `model.materialRules` 按材质名修正金属度与粗糙度。
4. **换镜头**：`camera.keyframes` 就是镜头脚本，`p` 是滚动进度 0–1，方位角 `az` 0° 正对车头、90° 车身左侧、180° 车尾；`r` 距离、`h` 高度、`ty`/`tz` 注视点、`fov` 视角。想加一个特写就在对应进度插一条。

最后把首页换成自己的预设：

```tsx
// app/page.tsx
import ShowcaseStage from "@/components/showcase/ShowcaseStage";
import { MY_CAR_SHOWCASE } from "@/components/showcase/presets/my-car";

export default function HomePage() {
  return <ShowcaseStage config={MY_CAR_SHOWCASE} />;
}
```

## 效果开关（配置里可整块关掉）

- `ground.ring: false`：不要车下方的钟面刻度环；
- `speed.tunnel: false`：不要速度线隧道；
- `speed.tunnel.bars`：主光条列表（角度、宽度、暖金或冷白），留空就只有很浅的虚线；
- `post`：曝光、Bloom、拖影强度；`zoom`：缩放范围。

## 约定

- 配置要能从服务端组件传给客户端组件，所以**正则一律写成字符串**（引擎内部再 `new RegExp(..., "i")`），不要直接写 `/.../ `；
- 随仓库分发的内置素材放 `public/mclaren/`；**导入的车型一律放 `public/uploads/mclaren/`**（运行期素材不进仓库、不进镜像，公开仓库审计会拦 100MB+ 的 glb）；
- 车型顺序与封面只以 `public/uploads/mclaren/showroom.json` 为准（顺序表 `order` + 导入车 `cover` + 内置车 `builtinMeta`），不要在前端另存一份偏好；
- 胶囊统一走「展示台胶囊标准」`components/showcase/capsule.css`：加 `class="fire-cap"` 即可（三态 = 常态淡底细描边 / 悬停只亮描边 / 已开启·当前选中·主操作 = 玻璃渐变底 + 亮描边 + 极轻外发光）；尺寸与排版留在各自布局类里，不要再写各自的底色与 hover。首页 HUD 与车型导入页共用这一套，深浅色分别按 `.showcase.light` 与 `:root:not(.dark)` 取变量；
- 章节导航在画面右侧竖直排列：每条 = 一根短横条，当前章节最长最亮（借鉴智能助手的消息轨），右侧那条细竖线是导轨；章节名平时不显示，悬停 / 键盘聚焦才浮在横条左侧（绝对定位，不会把横条挤得左右跳）；点击滚到对应章节（`.sc-nav` / `.sc-nav-tick` / `.sc-nav-label`）。
- 地面倒影（平面反射）：反射贴图**只填高度**（`ground.reflectionSize`），宽度由引擎按画面宽高比推（`reflectSizeFor`）—— 填正方形或填宽度都会让倒影在某一轴上被拉糊；贴图越高倒影越清晰（实测高度 768 → 1024 车身文字明显变清，宽度加 2.7 倍几乎没差别，因为掠射角下倒影在纵向被拉长）。另外整块地面的「天际线接色」只压在极掠射那一条带（`pow(fres, 2)`），否则中景地面被洗平、车身倒影会糊成一片灰雾。调参用 `?mclreflect=1024` 或 `?mclreflect=1638x1024`（只影响诊断），配 `?mclhud=1` 看当前贴图尺寸与帧耗时。
- 换车型是**原地换车**：`ShowcaseStage` 把 config 拆成「外壳签名」（镜头 / 灯光 / 地面 / 文案…）与「车型签名」（素材 + 车型参数），只有外壳变了才重建场景；单纯换车型走 `handle.setModel()` —— 引擎在同一个 WebGL 场景里先解析新车，解析完成后一次性撤旧车、挂新车（`mountCar` / `unmountCar`），镜头、地面、环境、HUD 全程不动，所以没有空白期、也没有加载层。车的挂载逻辑（尺寸归一化 / 材质规则 / 贴图上限 / 清漆 / 发光 / 拆轮子 / 车道朝向 / 包围盒）都收在 `mountCar` 里，**换车型不要另写一套**。
- 线框展示对所有导入车型走同一套自适应覆盖：已有密集拓扑直接复用；尾翼算法按几何连通件识别低面数部件，不依赖世界轴或固定长宽比，因此水平翼片、竖直端板和弯曲翼片都能统一选择 1–2 层规则四等分。左右镜像件即使导出尺寸有微小误差也使用一致的离散层级，避免最长边逐条切割造成的阶梯和杂线；补线层会替换对应原始大三角线，禁止两层重叠，且最多 16 个子三角形，保证远景不糊成色块。端板上低面数、细长且独立的凸起保留实体材质但不叠加线框。局部补线层不会修改原模型，也不会因尾翼与几十万面的车身合在同一网格就整块跳过；整车新增三角形预算为 100 万，换车 / 退出时释放。蒙皮或 Morph 模型保留原始拓扑，避免丢失顶点权重；`EXT_mesh_gpu_instancing` 在上传体检阶段拒绝，要求先转普通网格。
- 导入页“尾翼线框算法”折叠项把上述规则保存进每辆车的 `model.wireframe`：可调启用状态、目标边长、最大细分层级、连通件面数上限、整车预算，以及细长装饰件的面数 / 厚度 / 宽度 / 长度阈值。导入预览默认开启绿色叠加线框；修改参数后手动重载预览，确认后随车型写入 `showroom.json`。
- 冲刺隧道参照本地 `~/Downloads/0.临时/素材/迈凯轮/3D/0919.mp4` 的 14–21 秒：起步先绕至正后方，再落到左后 3/4 跟车位；高速时车在左下、消失点在右上，金色墙灯 / 冷白细线 / 路面短标线分层流动；松手先退光条，再恢复起步前的展示角度与缩放。
  - `speed.chaseCamera` 固定高速距离 / 高度 / 注视高度 / FOV，`chaseAzimuth` 与 `chaseLateral` 控制方位与横移；章节关键帧只负责静置浏览。`speed.response` 控制加速 / 减速响应，`topKmh` 为显示上限（参考约 340）。
  - `speed.tunnel` 的 `bars` / `lanes` 控制暖金墙灯与路标；`barSegment` / `auxCount` / `auxOpacity` / `dof` 控制密度、细线与光晕。光线相位按速度积分 `roadTravel` 推进，禁止用「累计时间 × 当前速度」（减速会倒退 / 跳相位）。
  - `__mcl.debug()` 可检查 `chase` / `roadTravel` / `tunnelStrength` / `tunnelEnabled` / `camera` / `carScreenBox`；停车后 speed / chase / travel / tunnelStrength 为 0，倒影恢复；`tunnel: false` 与 `?mcloff=tunnel` 同时关闭 3D 隧道和屏幕后期。
  - 合并轮胎按轮径与横纵跨度判断，不能用车长 / 车宽比判断单轮（MCL35M 的四轮合并网格恰好约 2.1，会被旧阈值 2.2 误判）。分出的网格保留原局部变换，再绕各自轮心自转。
- 交互约定：滚动 = 叙事推进，`拖拽` = 360° 环视，`⌘/Ctrl/Shift + 滚轮`（或 ZOOM 模式、双指捏合、左下角加减号）= 缩放，`空格 / 按住按钮` = 冲刺（车驶入隧道、轮胎转动），**双击画布（触屏双击）= 回到「固定机位」**：置顶过就回到置顶那一帧（角度 / 缩放由引擎 `setHomePose` 负责，章节进度由组件的 `onResetView` 把滚动带回去），没置顶才回到中立角度（yaw 0 / pitch 0 / zoom 1）。

## 切换车型（首页右下角）

- 车型清单 = **内置**（`presets/models.ts` 的 `SHOWCASE_MODELS`，目前只有随仓库分发的 MCL35M）+ **导入**
  （`public/uploads/mclaren/showroom.json` 里登记的车），两者合成一份后按 `order` 排序。
- 加车走导入向导即可，不用动 `SHOWCASE_MODELS`；内置车同样可以在导入页换封面，
  封面记在 showroom.json 的 `builtinMeta` 里，素材与渲染参数仍随仓库分发。
- 顺序只有一份来源：导入页拖动 → `PUT /api/showcase/models/order` → showroom.json 的 `order`；
  首页右下角车型条与导入页读同一个顺序函数（`resolveOrder`），**顺序表里缺项时内置车补在最前、其余补在末尾**
  （老版本保存顺序时会把内置车过滤掉，留下的脏顺序表靠这条兜底），所以开箱即用时排在最前的仍是内置车。
- 卡面：卡片上方是车型封面，高度按卡宽的 **52%** 给（`aspect-[100/52]`）——这是「车不被切」的临界比例，
  封面按宽度铺满时可见的纵向窗口 = 卡宽 × 52%，再小一点车头 / 轮胎就会被裁掉；没有封面时用车型代号占位。
- 每辆车的关键参数：`model.length`（整车目标长度）、`model.yaw` / `pitch`（朝向不对时修正）、
  `model.wheelPattern`（匹配轮子材质名，例如 `rims|tyres`、`Tyre`、`wheels`）、
  `wheelAxis` / `wheelLateral` / `wheelLongitudinal`（轮子自转轴与左右 / 前后判断轴）、
  `maxTextureSize`（贴图很大的模型收到 2048 省显存）。
- 轮胎网格可能包含单轮、一对或四轮；按每个网格自身坐标中的跨度和圆形截面判断，仅拆存在多轮的轴。MP4/5 前后轮分别位于不同父节点，不能混用其他网格的中线；共用轮胎材质的悬挂保持原状。测量、遮挡和速度验证详见 [隧道参考记录](showcase-tunnel-reference.md)。
- 选中的车型记在 `fire:showcase:model`（刷新保持）；排查缩放 / 朝向可以看 `__mcl.debug().carBox`。

- 自由镜头为右侧第六项：进入后固定叙事进度，普通滚轮缩放、触屏单指环视/俯仰和双指缩放；双击车身聚焦选中位置，独立「复位」按钮恢复初始构图，选择章节退出。最远距离按首帧 FOV、机位、车长与当前画幅估算，目标轮廓不小于 110px 或短边 20%，并限制倍率 1.2–5；以手机 390×844、平板 1024×768 及桌面截图检查最远构图。行驶刻度环在速度区间 4%–28% 渐隐，高速完全关闭。

- 交互手感：`interaction.ts` 精确积分指数阻尼，角速度单位为度/秒（俯仰弧度/秒），不累加每帧固定步长。拖动停留超过 80ms 再松手不续滑。双指开始时取消旋转，剩一指时从当前位置重新建立基准；双击空白不改变自由镜头。聚焦使用车体可见网格射线拾取，只在双击时遍历，不增加每帧拾取开销。
- 倒影交互档：拖拽、捏合、缩放与惯性期间，反射高度减半且不超过 512；继续逐帧绘制防止滞后。稳定 250ms 后恢复，切档间隔至少 250ms，主体渲染分辨率不因该策略改变。`tests/showcase-interaction.cjs` 检查 30–240Hz 同一释放状态的轨迹、缩放边界，以及实际指针处理函数的双指互斥/单指续接/取消/双击行为。


## 模型线框显示

首页右上角网格立方体进入独立浅灰（#e7e7e7）模型画布，临时隐藏环境几何与首页 HUD，直接渲染跳过后期和倒影。相机采用轨道逻辑：左键拖动环视；Shift / 中键 / 右键拖动平移焦点；Ctrl / ⌘ + 左键上下拖、滚轮或双指捏合沿当前视线直线 dolly；双击局部把它设为新焦点。缩放不会重算俯仰，因此从车头 / 车尾进入内部不走弧线。独立自由镜头支持初始距离 0.015–400 倍的连续缩放：可缩成远处小模型，也可推进座舱内部；near 随镜头距离在 0.0015–0.08 间动态调整，far 至少 5000 且随距离扩展，兼顾超近细节和极远全景。查看器另有相机跟随观察灯与下半球柔光，让底盘和车内在特定观察角度出现材质高光，不影响首页布光。关闭 / Escape 恢复原自由镜头、旋转、焦点和缩放。复位恢复查看器初始机位。显示面板：原生、叠加线框、纯线框。叠加与纯线框共用黑、浅灰、红、蓝、绿、黄六色；换色保持当前线框模式，原生模式点色块才进入叠加。所选颜色跨模式沿用，不再由背景主题覆盖。模式属于当前展示会话，换车时沿用、刷新回到原生。

`wireframe.ts` 共用模型几何，延迟创建线网子网格，保留拆轮后的父变换；叠加在不透明车漆之后绘制，并做微小裁剪空间深度偏移。纯线框使用不写颜色的实体深度和线网显示，抑制背面叠线。撤车前恢复原材质并移除子网格，控制器仅释放自身材质。网格来自本地 GLB 三角剖分，不尝试重建四边面或抓取 Sketchfab 的独立线框文件。

参考：Sketchfab [Model Inspector](https://sketchfab.com/blogs/community/inspect-models-and-textures-like-never-before/) 与 [Viewer API](https://sketchfab.com/developers/viewer/functions)。独立本地实现不依赖其服务。回归：`node tests/showcase-wireframe.cjs`。

显示面板材质现在跟随设置 → 配色，统一规范见 `docs/site-palettes.md`；选择 Liquid Glass 时采用玻璃风格：半透明背景模糊、边缘高光、圆形色珠；模式与颜色的选中玻璃层沿轨道移动，切换时短暂拉伸回弹，静止后停止动画。减少动态效果时禁用过渡；不支持背景模糊时使用实色兜底。该实现为网页 CSS 材质，不依赖 Apple 原生框架。

### Sketchfab 轨道操作补齐（2026-09-21）

- 查看器双击可见车身按命中点距离聚焦，使用查看器自身 0.015 的缩放下限，近距离不再被首页 0.55 下限拉远；双击空白背景拉远并保留焦点。
- 触屏两指中心的移动用于平移，同时按指间距离捏合缩放；松开一指从剩余触点继续环视。右键 / Shift 平移与 Ctrl / ⌘ 拖动缩放限定在自由镜头，首页普通拖拽保持原行为。
- 滚轮像素、行、页单位统一后计算缩放；实际仰角约束在接近正上 / 正下视角，边界停止俯仰惯性，避免初始机位角度造成单侧转不到或反向拖动空行程。
- 查看器远裁剪面随实际距离扩展，防止窄屏 400 倍远景超过裁剪面。置顶姿态同步包含章节进度，复位不会退回错误章节。
- `debug()` 提供 `target`、`inspector`、`clipping`，用于检查直线推进与焦点。实际操作回归：`node tests/showcase-interaction.cjs`；退出 / 复位隔离：`node tests/showcase-wireframe.cjs`。
- 操作依据：[Sketchfab 查看器自带导航说明](https://sketchfab.com/models/947489a42dab4dec8be1e5ed535fcfe1/embed)。本地实现对齐轨道交互，不声称复用其内部相机算法或精确阻尼参数。


## 大模型与原画内存策略（2026-09-22）

文件下载 MB 数不能表示解码后的内存。MP4/5 原文件 110,887,804 字节（110.89 MB / 105.75 MiB），16 张 4096×4096 贴图，仅 RGBA 像素即 1024 MiB，加完整 mip 链约 1365.3 MiB，尚未计算旧模型、解码临时数据、几何和后期缓冲。

- 原画保留源贴图尺寸。手机、平板和低内存设备加载未压缩原画前读取 PNG/JPEG 头估算纹理预算；超过 **128 MiB（含 mip）** 或无法估算时，要求 GPU 压缩副本并显示原因。这是保守的加载策略阈值，**不是实测所有设备的崩溃临界值，也不是下载文件大小阈值**。
- 显示副本使用 **KTX2 / UASTC level 3、关闭 RDO、Zstd 18**；不缩贴图、不减面、不量化几何，原始文件保留。UASTC 属于高质量有损，不能称逐像素无损。下载 gzip/Brotli 或 PNG 优化无法减少原始像素/GPU 驻留内存。
- MP4/5 本次副本 114,029,236 字节（114.03 MB），比原文件略大，但 16 张 4K 纹理和 mip 的 4×4 / 16 字节 GPU 块预算约 **341.3 MiB**，比未压缩 RGBA 少 75%；Chrome 平板模拟实际捕获到 208 次 mip 上传，共 357,914,368 字节，与该预算一致。具体 GPU 转码格式、纹理复用及其他缓冲会影响实际总显存；旧设备仍可能不足。
- 内存受限设备在解析新车前释放旧车。跨场景串行加载、逐张解码、销毁 ImageBitmap、释放过期结果；GPU 压缩纹理直接上传，不画到 Canvas 解压。原画画布仍保留最高 3 倍像素比，触屏 / 低内存设备总输出上限 300 万像素，桌面 800 万像素。
- 上下文丢失后退出模型展示并恢复流畅预览；手机/平板最多自动恢复一次，再失败给出明确重试入口。sessionStorage 保存尚未稳定完成的大模型加载，异常重开先恢复流畅模式。成功渲染稳定 5 秒后清除标记。

### 生成与部署

安装官方 KTX-Software 4.4+，使 `ktx` 可从 PATH 调用，然后运行：

```sh
npm run showcase:gpu -- public/uploads/mclaren/models/mclaren_mp45__formula_1.glb
```

脚本在同一 uploads 卷的 `mclaren/gpu/` 生成 `*-uastc.glb` 与 `.glb.json` 校验清单。发布前检查逐项网格索引/顶点属性一致、变换误差小于 1e-12、每张纹理宽高不变；不满足时拒绝发布副本。首页只启用匹配源文件大小、修改时间和输出大小的副本，源文件更新后旧副本自动失效。

**模型原件、GPU 副本和清单均不进 Git/镜像。** 部署到别的机器需在目标 uploads 卷重新生成，或同步 GPU 副本与清单且保留源文件修改时间。只推送代码不会把这份 114 MB 素材带到线上。导入入口仍拒绝外部压缩 GLB；内部生成的已校验副本单独使用。

KTX2 转码运行时由 Three.js 的 `basis_transcoder.js/.wasm` 随 `public/vendor/basis` 分发，生产 CSP 允许本源 WASM 与 blob worker。低档位仍使用原有轻量预览；缺少 GPU 压缩能力时停止原画加载并建议流畅模式。

回归：`node tests/showcase-memory.cjs`、`node tests/showcase-loading.cjs`。Chrome 手机/平板模拟可验证加载、切换和恢复流程，不能替代真实 iOS/Android 设备的内存压力测试。

本次纹理抽查：底盘与车身基础色贴图的解码像素 PSNR 分别约 55.09 / 49.82 dB。该指标只描述两张样本的误差，不等同于所有贴图逐像素无损，也不能保证任何缩放下肉眼零差异。
