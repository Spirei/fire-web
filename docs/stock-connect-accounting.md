# 港股通账户归属与迁移

已实现 Web 与共享接口的账户归属、人民币汇总、港股通添加入口及实际人民币结算。本地与线上数据库独立；本次已在线上容器内完成指定记录的备份、归属迁移和原始成交、资金流水比对。更新镜像不等于迁移持久化记录。

## 页面与币种

`records.market` 保留上市市场 HK、港股代码及港币报价；`records.account_market=CN` 表示港股通归属 A 股账户。股票名旁常驻「A/H」角标，悬停及无障碍名称说明港股通含义，不受普通市场角标隐藏设置影响。普通直接港股继续归属港股账户，自选股的上市市场分类仍按 HK。

我的持仓、资产页账户筛选、资产配置和 App 账户汇总使用账户归属。同一持仓只计一次，全局金额不会因为移动分类改变。我的持仓从当前市场搜索添加：A 股普通渠道只搜 CN；「A 股 · 港股通」只搜 HK，保存 CN 账户归属；总资产下直接渠道搜索全部市场。渠道保存在 URL。

人民币估值 = 数量 × 港币价格 × CNY 汇率 / HKD 汇率；成本和浮动盈亏同样换算，缺汇率返回缺失。价格与摊薄成本仍明确显示 HKD，人民币浮动盈亏为当前汇率下的估值，不能当作已核对的历史人民币投资回报。负摊薄成本的盈亏率按绝对成本作分母，与持仓详情一致。

## 成交与现金

新港股通成交必须补录券商实际人民币付款或回款净额（含费用），保存 `trade_orders.settlement_currency=CNY`、`settlement_amount`；港币价格、成交数量及费用继续保存原值。现金仅按实际人民币净额记账，不再次扣费，不用今天汇率估算结算。更正价格、数量、费用或方向时必须同时提供新的实际净额；仅改备注或时间保留原净额。

既有成交和 HKD 资金流水保留原始金额；缺少历史人民币成交单，不自动改币种或猜汇率。旧订单备注更正保留 HKD；显式更正经济金额需补实际人民币结算。删除订单按其原结算币种回退现金。

自动委托和自动股息无法确认券商实际人民币净额，港股通改为记录已成交；股息在持仓详情「交易」里选股息并填实际人民币回款。旧订单表导入遇到港股通记录会跳过并说明原因；导出保留账户归属、实际结算币种及净额。普通直接持仓原行为继续保留。

## 显式迁移

从部署的 fire-web 目录运行 `node scripts/migrate-stock-connect.cjs --user USER_ID --records ID1,ID2` 查看待迁移记录；添加 `--apply` 实际迁移。仅指定用户与记录，不按代码或名字推断渠道。运行前创建完整 SQLite 备份至 `data/migration-backups`，权限 0600，验证完整性后再修改。

迁移使用事务与版本校验，默认拒绝跨账户、非 HK、待成交委托和原账户固定核对金额；只写账户归属与版本，不改数量、价格、成本、原成交及资金流水。明确选择恢复相关券商自动市值时，可增加 `--restore-automatic-brokers`：仅恢复尚待迁移记录的原、目标券商账户，保留名称、全部现金账户及流水。原自动港股账户为空后移除无效配置；同一汇率下归属迁移前后总额必须一致，否则回滚。重复迁移不重写后续手动核对。

## 手动核对后的更新

重新核对关联账户时，保存输入金额及服务端估值、原币成交现金基准。后续金额 = 手动核对金额 + 当前来源金额变化 + 券商关联成交现金变化。券商来源金额是当前持仓市值，买卖引起的股票、现金变动相互抵销，费用只扣一次，股息只加实际净收入；港股通新增现金仍使用实际 CNY 净额。资金、银行卡与简化账本来源只应用对应原余额变化，不再叠加成交现金。

基准只保存在资产配置，不修改真实持仓或资金。`amountChanged=false` 的名称、计入状态修改保留原金额及基准；重新输入金额（即使与当前金额相同）才重新核对。完全卖出及资金余额归零后，已有基准的关联账户继续存在；缺市值或汇率返回缺失。旧核对记录缺少当时估值和现金基准，保持原值，重新输入核对金额后从本次开始更新，不补猜历史现金或汇率。

回归覆盖普通 A 股、直接港股、港股通、缺汇率、买卖股息及费用、现金同步、更正删除、已卖记录、历史原币保留、重复迁移、跨账户与版本冲突；真实迁移后逐项比对成交和现金完整记录，测试业务数据只进入临时数据库。
